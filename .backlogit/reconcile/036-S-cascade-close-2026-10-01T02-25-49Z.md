## Disclosed process-compliance gap (corrected 2026-10-01, found via Copilot review on PR #86)

The command actually run below is a **direct invocation of the underlying `backlogit shipment
ship` primitive**, immediately following the manually-executed `classify-close-path` step. This
is **not** equivalent to a conforming `shipment-reconcile mode: safe-close` execution. The
skill's `mode: safe-close` Step 0 requires taking a **fresh** snapshot of current state *at the
time of the safe-close call*, recomputing the canonical `CLASSIFICATION_BINDING` from that fresh
snapshot, and comparing it against the supplied binding — only on a match does it delegate to the
Cascade Close Sub-Procedure below. That recompute-and-compare step was **not performed**; the
binding above was computed once (during classification) and never revalidated before the direct
`shipment ship` call. This reproduces the same category of gap disclosed in the 035-S closure
(see
`docs/compound/2026-09-30-shipment-reconcile-skill-bypass-manual-substitution-risk.md`), with one
partial mitigation: unlike 035-S (where no binding was computed at all), this closure did compute
and record a canonical binding value — but computing it beside a direct call does not satisfy the
requirement, because the value was never used to gate or confirm the subsequent mutation.

The two-set gate, parent-ID preservation check, and archive-provenance checks below independently
confirm the **resulting archive state is internally consistent** (no unexpected archival, no
missing required archival, `parent_id` links intact). They do **not** retroactively establish that
the mutation was authorized through a bound safe-close revalidation — that gap is irreversible
once the mutation has executed and is disclosed here rather than claimed as closed.
