## Process Deviation Disclosure (added post-hoc, PR #84 review remediation)

**What the skill's contract requires.** Per `shipment-reconcile` SKILL.md's Classify-Close-Path
and Safe-Close mode sections, every caller of `mode: safe-close` must first invoke
`mode: classify-close-path`, obtain the returned `CLASSIFICATION_BINDING` (a SHA-256 digest
over the canonical snapshot), and pass that binding into `mode: safe-close`, which revalidates
it before any mutation and halts on drift. The Cascade Close Sub-Procedure — the code path that
actually calls the archival primitive — is reachable only from inside that bound `safe-close`
call. Unbound invocations must be refused (`RECONCILE_FAIL_CASCADE_UNBOUND`), never defaulted.
Ship's own agent contract (`.github/agents/_ship.agent.md`, Step 6 item 1.b) restates this: Ship
must never invoke the cascade primitive directly, and must never call `mode: safe-close` without
a `classification_binding`.

**What actually happened.** Step 0 below performed the equivalent classification predicates
manually (structural scan of `.backlogit/queue/` + `.backlogit/archive/`), correctly reaching
`CLOSE_PATH_VERDICT: CASCADE` / `VERDICT_REASON: FULLY_COVERED_ROOT`. However, no
`CLASSIFICATION_BINDING` was computed, and Step 1 invoked the `backlogit shipment ship`
cascade primitive **directly**, bypassing the mandated `mode: safe-close` call and its
pre-mutation binding revalidation (TOCTOU guard) entirely. This is a genuine process/contract
deviation, correctly flagged by Copilot review on PR #84
(discussion `#discussion_r4148317558`) — not a false positive.

**Disposition.** This is a disclosed P-005 process-compliance gap, not a confirmed
data-integrity failure:

* The classification predicates that `mode: classify-close-path` would have evaluated were, in
  fact, evaluated manually in Step 0 below, using the same exhaustive condition set the skill
  documents (root check, full-depth descendant coverage, no grandchildren, no linked
  deliberation) — the verdict itself is not in question.
* What was skipped is specifically the formal SHA-256 binding computation and its immediate
  pre-mutation revalidation. In this execution there was no time window between classification
  (Step 0) and mutation (Step 1) in which the underlying backlog state could have drifted — no
  intervening session, no other writer, single synchronous command sequence — and Steps 2–4
  below (two-set gate, `returned_ids` empty, `parent_id` preservation) independently re-verify,
  **after** the mutation, exactly the invariants the binding revalidation exists to protect
  **before** it. Those post-hoc checks all passed.
* No remediation of the already-archived data is possible or required — the archival result is
  independently confirmed correct by Steps 2–4. Remediation consists of: (a) this disclosure,
  (b) a new compound learning
  (`docs/compound/2026-09-30-shipment-reconcile-skill-bypass-manual-substitution-risk.md`) to
  prevent recurrence, and (c) an updated disclosure in the closure artifact's releasability
  evidence.
* **Corrective instruction for future closures**: even when no CLI gate wraps the
  `shipment-reconcile` skill, the skill's mode dispatch (`classify-close-path` → compute/carry
  `CLASSIFICATION_BINDING` → `safe-close`) must still be followed procedurally as documented —
  manual equivalence for the classification predicates is not license to also skip the binding
  computation and treat the cascade primitive as directly callable.
