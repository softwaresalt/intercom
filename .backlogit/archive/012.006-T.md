The CA469B3D fix in internal/pathsafe/root.go. TWO changes. (1) Re-form a remainder beginning with the UNC marker (matched CASE-INSENSITIVELY and INCLUDING the trailing separator) as a leading double-backslash plus the remainder after the marker, so extended-UNC input yields a genuine absolute UNC path instead of a relative string. (2) CLASS POSTCONDITION: if the stripped result is not a Windows-absolute form, return the ORIGINAL input unchanged. Keeping the extended-path form is absolute and simply fails the containment prefix match, i.e. fail-closed. This closes the Volume-GUID and GLOBALROOT shapes too rather than fixing only the one reported shape. The postcondition MUST use an OS-INDEPENDENT Windows-path classifier, NOT host filepath.IsAbs: stripUNCPrefix is a pure string function exercised by cross-platform tests, and using host IsAbs would make it retain the extended-path prefix on Linux and contradict the all-platform transform expectations. Implement a small local predicate recognising Windows-absolute forms (double-backslash UNC, and drive-letter-colon-backslash). Domain: code.
