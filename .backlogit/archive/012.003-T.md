The core ECE3DAB7 fix, in internal/pathsafe/pathsafe.go checkSymlinkEscape. TWO changes. (1) DEPTH-SCOPED PROBE: the FIRST loop iteration (ancestor == resolved, i.e. the final component) keeps os.Stat; every STRICT ancestor uses os.Lstat. This closes the bypass where a dangling intermediate symlink is walked past without re-resolving its target, while preserving the documented GO-14 final-component acceptance BY CONSTRUCTION (the first iteration IS the final component). (2) ENOENT-ONLY ASCENT: ascend ONLY when errors.Is(err, fs.ErrNotExist). Any other probe error (EACCES, EPERM, EIO, ELOOP, malformed reparse point) must REJECT, wrapping the OS cause, rather than silently being treated as absence. Today a non-searchable intermediate directory (root/private/link/new where private is unsearchable) lets the walk climb past a pre-planted escaping link. ALSO update the function doc comment IN THIS SAME TASK: it currently asserts 'os.Stat (not os.Lstat) gates each existence probe', which this change makes false; a security control must not carry a comment contradicting its code even transiently. KNOWN VERDICT CHANGE to assert deliberately: root/file.txt/sub (non-directory component) yields ENOTDIR which is NOT fs.ErrNotExist, so the walk will now REJECT instead of ascending-and-accepting; no existing test locks that case, and Windows may classify it as fs.ErrNotExist, so pin the intended behavior with a small cross-platform verdict test. Domain: code.
