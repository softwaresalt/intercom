Resolves 8472E0A1 item (g). OVER-REACH CORRECTED: revision 2 escalated this to a production REFUSAL of dollar-VAR/percent-VAR in the containment API; three reviewers rejected that. (1) Not authorized - 8472E0A1(g) asks only for a doc note or test confirming candidates must be raw unexpanded strings, a P3 advisory; no in-scope entry authorizes a verdict change in pathsafe. (2) Principle IV is NOT engaged - IV refuses paths that RESOLVE ABOVE OR OUTSIDE the root via expansion; a literal unexpanded segment treated literally resolves INSIDE the root (a directory literally named that), so literal treatment is already IV-compliant. The real vector is a CALLER expanding BEFORE calling pathsafe, which pathsafe cannot control. (3) A refusal predicate would cause false rejections - dollar-Recycle.Bin, dollar-WinREAgent and dollar-SysReset are real Windows directories and percent is a legal POSIX filename character. (4) It contradicted J2. Approach: test-first. Width: tests + docs. AC1 a doc note in pathsafe records that candidates MUST be raw unexpanded strings and that expansion is the CALLER's responsibility. AC2 a test pins that an unexpanded variable segment is treated LITERALLY, proving no accidental expansion occurs. AC3 a POSITIVE test proves legitimate literal dollar/percent filename segments (e.g. dollar-Recycle.Bin) still validate. AC4 ZERO verdict change (J2); no refusal class is added. AC5 the residual caller-side expansion gap is recorded in the Constitution Check as an explicit NAMED residual, not left implicit.
