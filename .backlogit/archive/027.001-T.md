Rewrite ONLY item 3 of the Staging Artifact Merge Gate in .github/agents/_orchestrator.agent.md (Step 1.5, lines 270-297) so every sub-step is bound to a NAMED ACTOR exercising only authority that actor already holds under P-010, and so the direct-push-to-default-branch arm is REMOVED.

THE TWO DEFECTS BEING FIXED.
(a) Item 3 names NO ACTOR. Items 3(a)-(d) direct someone to commit backlog files, push a branch, open a PR, wait for merge and pull - every verb subjectless. The default reading binds the Orchestrator, but P-010 states the Orchestrator "must not perform Stage or Ship work directly". Committing backlog artifacts is enumerated Stage work; pushing and opening a PR is enumerated Ship work. The gate has no legal executor.
(b) Item 3(e) directs "Attempt a direct push to `main` first" (line 287). The prohibition is P-010's and is unqualified: both the Ship MUST NOT and Stage MUST NOT lists forbid committing or pushing directly to the default branch. P-009 supplies the RATIONALE only - a direct push produces no merge commit, defeating the full-history/attribution/bisect guarantees and structurally bypassing P-009's own Ship Step 5 gate point. Item 3(e) is additionally redundant: its fallback body restates 3(a)-(d).

THE FIX. Replace item 3 with six actor-bound sub-steps: (a) uncommitted artifacts -> Stage commits in-session on its own branch; Orchestrator MUST NOT commit; halt STAGING_GATE_UNCOMMITTED. (b) local default branch ahead of remote -> Orchestrator detects and halts STAGING_GATE_LOCAL_MAIN_AHEAD, operator disposition; state the condition, do NOT attribute it to an agent (P-010 governs only stage/ship/orchestrator; the same state arises legitimately from operator activity). (c) unpushed Stage artifact branch -> OPERATOR pushes and opens the merge-commit staging PR, cited to the installed _stage.agent.md PR row; emit STAGING_GATE_AWAITING_OPERATOR, wait bounded to ONE Orchestrator cycle, then halt STAGING_GATE_OPERATOR_TIMEOUT. (d) merge -> OPERATOR approves and merges with a merge commit. (e) after merge -> Orchestrator does `git fetch origin {default_branch}` only; no write, no checkout. (f) NO DIRECT DEFAULT-BRANCH PUSH, grounded in P-010 by REFERENCE (not by quoting policy text into a second generated file), with P-009 as rationale; halt STAGING_GATE_NO_ROUTE, never fall back to a direct push.

AUTHORITY NEUTRALITY (NON-NEGOTIABLE). This task grants NO new authority to any role AND NARROWS NONE. An earlier revision asserted that "Ship's push/PR authority does not extend to a Stage artifact branch it did not create"; that clause is DELETED because chore/stage-* IS a chore branch and P-010 grants Ship "Create and checkout feature/chore branches, commit, push" unqualified. Asserting the narrowing would put two installed contract surfaces in direct disagreement. Do NOT reintroduce it. Do NOT modify .github/policies/workflow-policies.md.
