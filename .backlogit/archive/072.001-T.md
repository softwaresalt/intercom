Acceptance Criteria: (1) In internal/app/ui.go, add watchDone chan struct{} and stopErr error to localUI leaving ui.watchDone == nil in startUI until assemble/watchUI synchronously assigns ui.watchDone = make(chan struct{}) right before spawning the UI watcher goroutine, and guard (*localUI).failure() with a non-blocking check on <-u.done so u.err is never read unless u.done is closed. (2) In startUI(startCtx context.Context, ...), check startCtx.Err() before launching go prog.Run(), select on <-startCtx.Done() in the ready handshake (calling _ = ui.stop() and returning startCtx.Err()), and pass context.WithoutCancel(startCtx) to ui.feed.Start (calling _ = ui.stop() on error). (3) In (*localUI).stop() error, dispatch u.prog.Quit() asynchronously (go u.prog.Quit()) while the uiStopBudget timer runs (rather than calling u.prog.Quit() synchronously before starting the timer, since Bubble Tea's Quit() calls blocking Program.Send), and bound the post-Kill wait on <-u.done with uiKillWaitBudget (uiStopBudget): when uiStopBudget expires before <-u.done, stop() calls u.prog.Kill() (which cancels the program context and unblocks any parked Quit()) and waits up to uiKillWaitBudget for <-u.done; when <-u.done closes in either the uiStopBudget wait or the post-Kill uiKillWaitBudget wait, wait on <-u.watchDone only when u.watchDone != nil (closed by assemble.go's UI watcher goroutine after recording any runtime TUI error) so startup cleanup in startUI before watcher registration never deadlocks while a runtime TUI error is always joined into App.Err(); when the post-Kill timer expires on uiKillWaitBudget after u.prog.Kill(), stop() records and returns a non-nil timeout error (u.stopErr) after closing u.feed without waiting on u.watchDone, and both teardown() (joined into the startup teardown error) and supervise() (joined into a.err before close(a.done), via a.addUIErr(u.stop()) / a.addErr(u.stop()) before a.takeUIErr() / a.takeErrs()) propagate that timeout error into the returned error and App.Err(). (4) Add unit tests in internal/app/tui_test.go covering startUI cleanup without deadlock on pre-cancelled startCtx, cancellation during the ready handshake, and feed.Start failure before watchUI is registered, plus concurrent TUI failure joined into a.Err(), a stalled-before-Quit regression test where u.prog.Quit() blocks indefinitely (simulating a TUI event loop that stalls before receiving Quit) asserting that stop() still escalates to Kill() after uiStopBudget and completes within uiStopBudget + uiKillWaitBudget without hanging on Quit(), and a wedged-TUI test (where u.done stays open after Kill()) asserting BOTH bounded completion within uiStopBudget + uiKillWaitBudget AND a non-nil shutdown error (stop() != nil and App.Err() != nil).
