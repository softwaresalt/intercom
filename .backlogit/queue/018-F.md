- No 'git push origin main' or equivalent direct-push path exists for Stage anywhere in the contract corpus.
- All Stage artifact persistence uses a dedicated branch plus PR, explicitly including the case where NO shipment is formed.
- THE NO-SHIPMENT ROUTE IS EXECUTABLE END TO END, NOT ONLY AUTHORIZED (rev 6). Orchestrator Step 1.5 receives the Stage artifact branch EXPLICITLY as a staging handback record (stage_branch, stage_base_commit, stage_head_commit, stage_outcome, stage_artifact_paths) and inspects a BRANCH-SPECIFIC range (origin/main..HEAD, equivalently origin/main..$STAGE_BRANCH, proven equal by a HEAD assertion) rather than the default branch against its own remote-tracking ref, which is empty by construction once Stage commits on chore/stage-*. The branch-resolution block sits ABOVE step 1's dirty/clean split, so its rev-parse --verify and HEAD-equality guards run on the dirty path too - the path that actually mutates the repo. Step 1's dirtiness pathspec is the FIXED STAGE_ARTIFACT_ROOTS constant (.backlogit/ docs/plans/ docs/decisions/ docs/memory/), not .backlogit/ alone and NOT the handback field (rev 7), so neither a docs-only run nor a narrow handback can be reported clean. Step 4 carries a SECOND VERIFICATION ARM for stage_outcome: no-shipment - a concrete post-merge target that names NO shipment_id. No self-deadlock and NO WEDGE: Stage creates/checks out/commits its artifact branch and returns base/head/branch/outcome; the Orchestrator pushes, opens the PR, waits for merge, and verifies on origin/main. EVERY handback field has a deterministic default so the HANDBACK RESOLUTION never halts; when the HEAD resolution yields the default branch, stage_branch stays UNRESOLVED and the run routes to step 3a's create-arm - exactly the pre-change behaviour - and the default branch is NEVER substituted for the artifact branch.
- THE NO-SHIPMENT ARM PROVES CONCRETE FILES ACROSS THE WHOLE SESSION, NOT DIRECTORIES AND NOT ONLY THE TIP COMMIT (rev 7, aggregate at rev 8). The Orchestrator CAPTURES AND RETAINS stage_base_commit (git rev-parse HEAD) IMMEDIATELY BEFORE INVOKING STAGE; that retained value is AUTHORITATIVE over any Stage-reported one. The arm runs SIX ORDERED CHECKS, any failure halting with STAGING_GATE_FAIL: rev-parse --verify of stage_head_commit; rev-parse --verify of stage_base_commit, rejecting an UNRESOLVED base; merge-base --is-ancestor {stage_base_commit} {stage_head_commit} (RANGE VALIDITY); merge-base --is-ancestor {stage_head_commit} origin/main (COMMIT ANCESTRY); derivation of AGGREGATE = git diff --name-only -z --diff-filter=d {stage_base_commit} {stage_head_commit} -- {STAGE_ARTIFACT_ROOTS}, halting when EMPTY; and VERIFY_SET resolution followed by git cat-file -t "origin/main:{path}" for EVERY path, requiring exit 0 AND output exactly 'blob' (READABILITY AND FILE-NESS). stage_artifact_paths is a NON-EMPTY set of CONCRETE repository-relative FILE paths changed between the two commits and is NEVER defaulted to a directory list; when the handback supplies it, the set must contain only file paths (no trailing slash, no bare root, no glob) under STAGE_ARTIFACT_ROOTS and must be EQUAL to AGGREGATE - equality, not subset, because a subset check accepts both an invented path and a silently shrunken set. DIRECTORIES, EMPTY SETS, OUT-OF-ROOT PATHS, AND CHANGED-FILE-SET MISMATCH ARE ALL REJECTED. THREE ALGORITHMS ARE EXPLICITLY FORBIDDEN AND MUST NOT REAPPEAR: git show origin/main:{path} (it EXITS 0 ON A TREE - verified - and those four directories exist on origin/main in every repository, so the rev-6 loop was a guaranteed pass that read no file the Stage run wrote); a DIRECTORY-PREFIX default for the path set; and a SINGLE-COMMIT git diff-tree derivation over stage_head_commit alone, which verified only the tip commit's files and left every artifact written in an earlier commit of the same session covered by ancestry alone - the very property the per-file check exists because ancestry does not provide. The RANGE form origin/main..{stage_head_commit} is equally refused: EMPTY BY CONSTRUCTION post-merge. The TWO-TREE diff is chosen because it reads IDENTICALLY BEFORE AND AFTER THE MERGE. Step 3a RE-RECORDS stage_head_commit as git rev-parse HEAD after committing, PRESERVES stage_base_commit unchanged (or sets it to the HEAD captured BEFORE that commit when it was UNRESOLVED), and discards any reported paths, so the recomputed set is the aggregate over the preserved base. All new halts are in VERIFICATION, not in handback defaulting, so the never-halts invariant above is intact.
- THE NO-SHIPMENT OUTCOME IS REACHABLE, NOT ONLY SPECIFIED (rev 8). As installed, _stage.agent.md Step 5.5 declares shipment assembly MANDATORY whenever the registry advertises features.shipments: true, and Step 6's pre-summary gate HALTS when no shipment_id exists - so stage_outcome: no-shipment could never be emitted and the entire verification arm above was dead prescription. 018.009-T scopes Step 5.5's mandatory rule to a harvest that PRODUCED ITEMS (preserving its empty-harvest / unresolved-P-003 guardrail VERBATIM as the discriminator), requires shipment_id in Step 6's gate ONLY when stage_outcome is shipment, emits the COMPLETE handback record plus an explicit terminal statement for a no-shipment run, and does NOT route the operator to Ship. FAILURES STAY FAILURES: P-003 lineage violations, harvest failures, and a missing required shipment after a NON-EMPTY harvest continue to HALT and are NEVER recorded as no-shipment. no-shipment is a SUCCESS terminal for a run that had nothing to ship, never a re-label for one that failed.

- THE OUT-OF-ROOT HALT HAS AN ACTUAL DETECTOR (rev 10).
