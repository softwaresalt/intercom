Resolves 11ECB954. RULE DEFINITION CORRECTED: revision 1 defined the rule as 'a negation that re-includes a path already matched by an earlier ignore pattern' - which is the definition of EVERY functional gitignore negation, since git only gives a '!' line effect when a preceding pattern already ignores the path. Implementing it as stated would ban all effective negations, the exact outcome D-E forbids. CORRECTED RULE - old-vs-new behavioural differential using git's OWN matcher rather than a gitignore engine reimplemented in bash (also the plan's clearest YAGNI violation): no path ACTUALLY IGNORED AT BASE-REF may become UN-IGNORED AT HEAD-REF. Approach: test-first, extending the existing self-test fixture harness. Width: script + fixtures. AC1 PART 1 canonical sensitive-path probe - a fixed committed denylist asserted at head-ref with 'git check-ignore --no-index' (which does NOT require the path to exist). THE DENYLIST CONTAINS ONLY PATHS GUARANTEED IGNORED BY HEAD PLUS THE PRESERVE-ONLY GAP-CLOSURE TASK, so it can never depend on droppable content: .env, .env.local, config.toml (all three MEASURED ignored at HEAD) plus .claude/instructions.md, .github/copilot/settings.local.json, .autoharness/gates/pipeline-topology-force-audit.log, .backlogit/hooks_queue.jsonl (guaranteed by the gap-closure task, which lands first and is non-droppable). Seven entries - non-vacuous, and every one survives a stowaway drop. STANDING RULE: the denylist may NEVER reference a pattern introduced by droppable content. EXCLUDED with reasons: '*.pem' and 'id_*' match NO pattern in this repo; '.backlogit/*.db' as a glob is not matched; 'plugin/.mcp.json' is DELIBERATELY un-ignored by an operator-authorized negation; and .mcp.json/.copilot/.engram/backlogit.db/.autoharness-staging/.vscode are ignored ONLY by droppable stowaway lines (measured NOT ignored at HEAD). AC2 PART 2 existing-file differential - any path actually ignored at base-ref must still be ignored at head-ref; base-ref status evaluated in a DETACHED WORKTREE since git check-ignore reads the working tree, not a ref. AC3 LANDING PRECONDITION (mandatory): --self-test asserts EVERY denylist entry is ignored at HEAD, converting a mis-specified denylist into a mechanically detected defect. AC4 PER-PATH evaluation, literally quoted - git check-ignore exits 0 if ANY argument is ignored, so a batched invocation would mask an entry that silently became un-ignored, and unquoted glob-shaped entries would shell-expand. AC5 the checker reports the two counts SEPARATELY and fails if the DENYLIST count is zero (revision 2 specified only 'git ls-files --others --ignored --exclude-standard' at base-ref, which returns EMPTY on a fresh CI checkout, so the gate would have reported green on every real PR). AC6 'git ls-files -i -c --exclude-standard' is empty. AC7 a fixture that un-ignores a previously ignored EXISTING file is REJECTED, naming the path and the negation line. AC8 a fixture adding a negation for a path that does not currently exist and is not on the denylist is ACCEPTED. AC9 NO waiver mechanism is built (YAGNI, and an unowned bypass in a security gate); a deliberate un-ignore that trips the gate is RECORDED AND ESCALATED TO THE OPERATOR. AC10 the checker header records its boundaries: root .gitignore only, pull_request-gated, and part 2 inert on a clean CI checkout. AC11 --self-test passes and stays wired into CI.
