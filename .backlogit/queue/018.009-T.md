(3) Add an actor note on the PR row recording that the Orchestrator (pipeline invocation) or the operator (direct invocation) - never Stage - pushes the branch and opens/merges the staging PR, so the corrected Git row does not imply a forbidden Stage action. The PR row is the ONE row exempted from the otherwise-unchanged requirement in AC-B3.3; its prohibition is unweakened. (4) REV 6 - add to Stage's STEP 6 (Summary) session-output contract one required line emitting the STAGING HANDBACK RECORD the Orchestrator's Step 1 now consumes (018.007-T, AC-B1.5): stage_branch, stage_head_commit, stage_outcome (shipment|no-shipment), stage_artifact_paths, and shipment_id when one was formed. This is the ONLY edit outside the Role Boundary table; without it the Orchestrator's handback requirement has no producer and every pipeline run falls into the STAGING_HANDBACK_DEGRADED path. It transfers NO authority - emitting a branch name is not pushing, opening, or merging anything. (5) REV 7 - the SAME Step 6 line fixes the SHAPE of stage_artifact_paths: a NON-EMPTY list of CONCRETE repository-relative FILE paths - the files Stage committed in stage_head_commit - NEVER directory prefixes, and it names the derivation Stage uses to produce them: git diff-tree --no-commit-id --name-only -r -z --diff-filter=d {stage_head_commit} filtered to .backlogit/ docs/plans/ docs/decisions/ docs/memory/. Naming the producing command here is what makes the consumer's SET-EQUALITY check (018.007-T AC-B1.10) satisfiable by construction rather than by coincidence: two surfaces computing the same set from the same commit with the same command cannot disagree. A producer left free to emit directory prefixes would either fail that check on every run or force it to be weakened back into the always-true form rev 7 removed. Still no authority transfer - emitting a file list is not pushing, opening, or merging anything.
