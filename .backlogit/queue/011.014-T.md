Resolves 309FBF5A(ii). TARGET CORRECTED - four reviewers independently found revision 1's rule denied the wrong package. It denied only github.com/github/copilot-sdk/go/rpc, but the credential-consuming, shell-executing surface (NewClient, Client.Start, CreateSession, SessionConfig.OnPermissionRequest) lives in the ROOT package github.com/github/copilot-sdk/go, imported by client.go, fixture.go, permission.go and every probe test. Only permission.go imports /rpc, and it sits inside the allowlisted directory - so the revision 1 rule matched ZERO files and would have shipped as false assurance for the boundary C3's exit contract depends on. Approach: configuration + durable negative fixtures. Width: lint config. AC1 the rule denies the ROOT PREFIX github.com/github/copilot-sdk/go (which subsumes /rpc), exempting internal/copilotprobe via depguard's NEGATED, ABSOLUTE-PATH-ANCHORED files form - approximately files: ['\', '!**/internal/copilotprobe/*.go']. A bare internal/copilotprobe/*.go pattern will NOT match, since depguard evaluates files against absolute paths. AC2 depguard is ADDED TO linters.enable - .golangci.yml uses 'default: standard' which excludes it; a rule under settings alone silently does nothing and would still satisfy a naive 'lint passes' AC. AC3 TWO durable committed fixtures, both asserted in CI: (i) a file outside the allowlist importing the SDK root package makes golangci-lint EXIT NON-ZERO (deny direction); (ii) a file under internal/copilotprobe2/ ALSO fails (proves the allowlist is anchored and has not silently widened to a sibling). A one-shot manual demonstration is insufficient - it cannot detect config drift. AC4 golangci-lint run ./... passes on the current tree. AC5 the allowlist carries a comment naming C3 as the removal trigger, and states that DEPGUARD OWNS Go package-import boundaries while check-retired-architecture.sh owns retired-architecture/path-surface contamination.
