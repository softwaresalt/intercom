## Post-merge closure — disclosed process-compliance gap (corrected 2026-10-01)

035-S's closure disclosed a process-compliance gap: the cascade primitive was invoked directly
and unbound, with no `CLASSIFICATION_BINDING` computed at all
(`docs/compound/2026-09-30-shipment-reconcile-skill-bypass-manual-substitution-risk.md`). This
shipment's closure **reproduced the same category of gap** — it did not close it, despite an
earlier draft of this memory claiming otherwise (corrected here via Copilot review on PR #86):

1. **a1 covering-feature completion gate** ran first (all 5 conjunctive conditions held),
   transitioning `046-F` `active -> done` via `backlogit move` *before* classification.
2. **classify-close-path** (manually executed — no CLI/gate subcommand implements this mode in
   this workspace; SKILL.md's documented algorithm was followed step-by-step): verdict
   `CASCADE` / `FULLY_COVERED_ROOT`. The canonical `v1` `CLASSIFICATION_BINDING` was computed
   over the **post-a1** snapshot (046-F status=`done`) — an important ordering lesson: a first
   draft computed it pre-a1 (status=`active`) and had to be discarded/recomputed once the
   order dependency was recognized.
3. **Direct cascade invocation (the gap)**: `backlogit shipment ship 036-S --sha 5fdd75a...` was
   called **directly** — not from inside a conforming `mode: safe-close` call that would have
   freshly recomputed the binding from a new snapshot and compared it against the value computed
   in step 2 before delegating to the Cascade Close Sub-Procedure. That recompute-and-compare
   step never ran. Results: `returned_ids=[]`; `archived_ids` exactly equals both `allowed_ids`
   and `required_ids` (15 items: 13 tasks + `036-S` + `046-F`); all `parent_id` links preserved
   post-close — this confirms the **resulting archive state's data integrity**, but does not
   retroactively establish that the mutation was authorized through a bound safe-close
   revalidation.
4. Pre-mode and post-mode reconciliation both returned `PROCEED`; the P-007 deleted-archive-file
   guard found zero deletions (git showed only additions/renames).
5. Final shipment/feature state: `036-S` `status: archived` / `archived_status: shipped`;
   `046-F` `status: archived` / `archived_status: done`.

## Key learnings (durable; see docs/compound/ for the standalone captures)

* **A manually-computed binding recorded beside a direct cascade call is NOT a bound sequence** —
  this is the single most important correction from this session. Reasoning that "no state
  changed between classification and invocation, so recomputation would be identical" is
  *exactly* the failure mode the safe-close revalidation step exists to guard against, because
  that claim is unverifiable from inside the same session asserting it. The mandated step must
  be literally executed (a fresh snapshot, a real recomputation, an explicit comparison), not
  reasoned about as unnecessary. This gap recurred across two consecutive shipment closures
  (035-S: no binding computed at all; 036-S: a binding computed but never revalidated) —
  confirmed in `docs/compound/2026-09-30-shipment-reconcile-skill-bypass-manual-substitution-risk.md`
  ("Recurred in 036-S" section).
* **Binding-before-cascade-call ordering relative to a1 is still correct and worth preserving**:
  computing `CLASSIFICATION_BINDING` requires the *exact* post-a1 declared status of the covering
  feature, because the binding is a snapshot contract a genuine safe-close call would revalidate
  against. Compute it after a1 runs, never before — this ordering lesson stands independent of
  the safe-close-invocation gap above.
* **Cascade primitive internally no-ops on an already-`done` feature member**: running a1 first
  (feature -> `done`) does not double-mutate when the cascade engine's own
  `setArtifactStatus` call later targets the same feature — safe to sequence a1 strictly
  before the cascade invocation.
* **Full-depth descendant coverage must be scanned exhaustively**, not just direct children —
  confirmed via an exhaustive `parent_id` grep across both `.backlogit/queue/` and
  `.backlogit/archive/` before classifying this manifest as a fully-covered root (no
  grandchildren existed, but the check itself is the load-bearing step, not the specific
  absence of results).
* No new standalone compound entry was required for 036-S's own build/review work — the
  Copilot findings on PR #85 were faithful parity confirmations (stash-captured per P-021, not
  novel problem/solution pairs). The closure-procedure gap above, however, *did* warrant updating
  the existing 035-S compound entry (not a new one) plus a new stash capture (`D10D3AFC`) for the
  structural remediation recommendation.
