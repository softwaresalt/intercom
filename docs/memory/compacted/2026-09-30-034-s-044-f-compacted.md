## Key learnings (durable; see docs/compound/ for the standalone captures)

* **MSYS/Git-Bash path translation is not simply `/c/...` string substitution.** A
  drive-letter-to-POSIX-path converter (`toBashPath()`) had an off-by-slice bug that silently
  produced `/c:/Users/...` instead of `/c/Users/...`, defeating a PATH-shim fake-`go` binary
  without failing loudly — a test coincidentally still passed because the real system `go`
  produced the same exit-2 signature the test expected. Also, `pwd -W` (Windows-only) plus
  `os.SameFile` identity comparison is required instead of string equality, because
  `cd ... && pwd` under Git-Bash's `/tmp` mount alias, and 8.3 short-name vs long-name user
  profile aliasing, both defeat naive path-string comparison.
* **`unicode.IsUpper`/`IsLower` in Go under-match CPython's `str.islower()`/`isupper()`** because
  Go's functions are Lu/Ll-category-only, while CPython additionally honors the `Other_Lowercase`
  / `Other_Uppercase` derived Unicode properties (caught by golden case U+2071 SUPERSCRIPT LATIN
  SMALL LETTER I). Fixed with a supplementary derived-property table (`case_table.go`).
* **Bare `bash` on PATH is ambiguous across Windows dev boxes**: this machine resolved it to the
  Windows-builtin WSL2 shim (no Go toolchain, no Windows-path argument translation), not Git for
  Windows' bash. CI (`ubuntu-latest`) has only one `bash` and is unaffected; local script/test runs
  must pin `C:\Program Files\Git\bin\bash.exe` explicitly.
* Windows-native `python.exe` applies universal-newline `\n`→`\r\n` translation to subprocess
  stdout/stderr regardless of which bash invokes it; golden captures must normalize this.
* `gofmt` gives false positives on a CRLF checkout; verify against an LF-normalized copy (or, as
  done here, a `git archive`-extracted tree) before trusting `gofmt -l .` output — and don't let
  that suppress a genuine parse-error/BOM defect that's also masquerading as a formatting issue
  (the `filebased/*.go` malformed-fixture rename in fix-ci cycle 1 was a real defect, not a false
  positive).
* `syscall.SysProcAttr.Setpgid` does not exist on Windows; OS-specific signal-handling test helpers
  need `!windows`/`windows` build-tagged files, and the Windows side must honestly report
  `signalTestsSupported() == false` (SKIP) rather than fake a PASS. The underlying bash
  trap/cleanup logic was independently hand-verified via WSL2 (`set -m` + `kill -INT/-TERM -- -$PGID`)
  since the Windows dev box cannot exercise it.
* backlogit's parent-feature-active → all-children-visible status-field behavior flips sibling
  tasks from `queued` to `active` cosmetically when any one sibling under the same active feature
  is marked `done`; this is not a genuine multi-claim and did not affect single-threaded,
  dependency-ordered execution. Real dependency enforcement stayed gated at `move --status done`
  time.
