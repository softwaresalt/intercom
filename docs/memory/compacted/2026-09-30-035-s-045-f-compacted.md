## Key learnings (durable; see docs/compound/ for the standalone captures)

* **Task-completion catch-up**: all 11 tasks were discovered still `status: active` at the start
  of post-merge closure (an earlier in-session context compaction had interrupted Step 4.5's
  per-task completion updates). Caught and remediated before the a1 covering-feature gate ran —
  a good general lesson: always re-verify manifest member status explicitly during closure rather
  than trusting the build loop completed every bookkeeping step.
* **Narrative-only Copilot findings recur**: round 6 and round 13 both produced genuine, in-scope
  findings that existed only as unlabeled prose in the review body, with zero inline comments or
  threads. Round 13's finding (a silently-dropped caller-cwd git precondition guard in
  `scripts/check-retired-architecture.sh`) was a real regression, empirically verified and fixed
  (`5632342`). See the new compound entry
  `docs/compound/2026-09-30-copilot-review-body-prose-signal-vs-gate-verdict.md`.
* **Don't judge review completeness by body-text "richness"**: round 14's near-empty boilerplate
  body was genuinely the first fully clean round (confirmed via the `autoharness gate
  copilot-review` programmatic verdict) — trust the gate, not prose length/tone.
* **A hand-traced, would-be-rushed fix can be worse than the bug it targets**: the `walkTable`
  ancestor-reopening-desync candidate fix was prototyped and confirmed to regress a fail-closed
  parse-error into a silent-skip security bug. Deliberately deferring it (stash `9FC28DB9`, HIGH
  priority) was the correct call under the review-fix cycle budget rather than rushing a patch.
* **Stash entries live in a separate store** (`.backlogit/stash.jsonl`, queried via `backlogit
  stash list`/`get`), distinct from the regular artifact queue/archive (`backlogit get`/`list`).
  An initial closure-time lookup against the wrong store looked like a data-integrity gap
  (captures claimed in the PR body but "not found") before the correct command confirmed all 5
  entries were genuinely present with full P-021 payloads. Use `backlogit stash get/list`, never
  plain `backlogit get`, to verify stash-entry persistence.
* **Manual `shipment-reconcile` classification was performed, but its mandated binding/safe-close
  sequencing was NOT** (disclosed process deviation, found via Copilot review on PR #84): no
  `classify-close-path` autoharness gate is installed in this workspace, so the classification
  predicates (Step 0) were correctly evaluated manually per the skill's own documented protocol
  (structural scans of `.backlogit/queue/` + `.backlogit/archive/`), consistent with 034-S's
  precedent. However, the skill's own mode-dispatch discipline — compute/carry a
  `CLASSIFICATION_BINDING`, never call the cascade primitive except from inside a bound
  `mode: safe-close` — has no "no CLI gate" exception, and was skipped: the cascade primitive
  was invoked directly instead. Not retroactively repairable, but independently re-verified
  correct via the report's own post-hoc two-set-gate / `parent_id` / `returned_ids` checks. See
  the new compound learning
  `docs/compound/2026-09-30-shipment-reconcile-skill-bypass-manual-substitution-risk.md` for the
  corrective instruction.
