## Key decisions and rationale

* **Canonical-contract remaster (revision 6)**, after 4 consecutive plan-review FAILs where
  each remediation was validated only against the finding it answered and never against the
  whole document (3 of attempt 3's 4 P0s, and 3 of attempt 4's 4 P0s, were introduced by the
  *previous* revision's own fixes). A new `docs/plans/2026-09-16-017-S-closure-canonical-contract.md`
  became the authoritative decision register; the plan was rewritten from it (1095 → 624
  lines) with unique monotonic step/gate/AC IDs. This is the durable process lesson: **every
  remediation pass requires a whole-document consistency sweep, not just a targeted fix.**
* **`OPERATOR_ACCEPTED_RESIDUALS` (contract `D-L7`)** — introduced as a bounded
  PASS-equivalent disposition for eligibility ground 3 (governing closure plan review),
  after scoped final verification of the attempt-10 P1 remediations passed. Explicitly
  confers no claim authority, no `PA-017-CASCADE` scope widening, and no exemption from
  re-measuring the nine escrow conditions at invocation.
* **`PA-017-CASCADE` escrow** — held destructive-cascade approval, released only when all
  nine conditions are re-measured fresh at the point of invocation (never inherited from a
  prior session). Ship's post-merge session re-measured and satisfied all nine; see the
  closure artifact's risky-action record for the per-condition PASS table.
* **Claim is a one-way door** — no shipment "unclaim" path exists in `backlogit`
  (`shipment` subcommands: `add|claim|create|get|list|return-blocked|ship`; exits from
  `active` are only `shipped` and `abandoned`, the latter terminal/destructive/unapproved).
  This drove the requirement that every preflight gate (PF-0…PF-12) be satisfied *before*
  claiming, not discovered as a rollback need after.

## Failed approaches (do not repeat)

* **"Release the claim via the shipment's own unclaim/return path"** — this operation does
  not exist; proposed twice across the review lineage (attempt 2 revision), FAILed both
  times, independently flagged by multiple reviewers each time.
* **`backlogit move <id> --status archived`** is *not* an archive operation (the correct one
  is `backlogit archive <id>`). A probe run using `move` silently measured a plain all-queued
  manifest and produced a false FAIL; a fixture-validity gate was added afterward to abort
  probes before measuring on an invalid fixture.
* **Git branch-switch under uncommitted D-G6 artifacts** (`run-log.md` intentionally
  uncommitted until S-21.5) — `git checkout main` fails with "local changes would be
  overwritten." Resolved non-destructively via `git stash push -u` → checkout/create branch
  → `git stash pop`. Reusable pattern for any future closure-branch creation under this
  contract.
* **Mismatched pre/post backlog-path capture methodology** (`git ls-tree` for pre vs.
  filesystem glob for post) produces spurious diffs from untracked debris (`.lock` files,
  checkpoint JSONs). Reliable method: `git diff --cached --name-status {pre_sha} --
  .backlogit/queue/ .backlogit/archive/` (tracked-file-only comparison).
