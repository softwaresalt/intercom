## 2. Local capture-environment notes (not repo behavior)

Two local-machine quirks were discovered and corrected for during write-path stream capture
(`M1-T3`). Neither reflects a change to the Python engine's actual behavior; both are noted here
for reproducibility on a different machine:

1. **Bash resolution**: this machine's bare `bash` on `PATH` resolves to `C:\Windows\System32\bash.exe`
   (WSL2), which has no Go toolchain installed and uses a separate Linux path namespace (so a
   Windows absolute path like `C:\...` isn't resolvable as a script argument). All bash
   invocations in the write-path generator instead explicitly target
   `C:\Program Files\Git\bin\bash.exe` (Git for Windows / MSYS), which shares the Windows `PATH`
   and can locate `go`.
2. **`python3` alias-stub shadowing**: under Git for Windows bash, `command -v python3` resolves
   to the Windows Store app-execution-alias stub (`...\WindowsApps\python3`) before it would ever
   reach a real interpreter, because this machine's Python install provides only `python.exe` (no
   `python3.exe`). The wrapper's `PYTHON_BIN` selection (`command -v python3` then `command -v
   python`) never falls through to the real `python.exe` while that stub directory is on `PATH`.
   The generator excises the `WindowsApps` alias directory from the subprocess `PATH` it passes to
   bash so the wrapper correctly falls through to the real `python` interpreter.
3. **Windows `python.exe` universal-newline stdout translation**: captured subprocess stdout/stderr
   from the Windows Python build applies `\n` → `\r\n` translation purely because the interpreter
   itself is a native Windows build (this happens independent of which bash flavor invokes it). The
   real engine runs under Linux `python3` in CI/production, which never inserts `\r`. The generator
   normalizes captured stream bytes (`\r\n` → `\n`) so the golden reflects the portable, `\n`-only
   behavor the Go port must match, not a local Windows artifact.

None of these three items changed the *logical* output captured (selectors matched, exit codes,
line numbers, PASS/FAIL wording) — they only affected which interpreter answered the call and
what raw bytes a Windows-hosted subprocess pipe carried.

        masked = gomask.mask_go_non_code(text)

# ---------------------------------------------------------------------------

# Rune corpus: every class named in the plan (M1-T2), each rune individually
# assigned in Unicode 15.0 or earlier (all of these predate 15.0 by a wide
# margin).
RUNE_CODEPOINTS = sorted(set(
    list(range(0x00, 0x20))  # ASCII controls
    + [0x7F]
    + [0x1C, 0x1D, 0x1E, 0x1F, 0x85, 0xA0, 0x1680]
    + list(range(0x2000, 0x200B))
    + [0x2028, 0x2029, 0x3000]
    + list(range(0x41, 0x5B)) + list(range(0x61, 0x7B))  # ASCII letters
    + list(range(0xC0, 0x100))  # Latin-1 supplement letters

    + list(range(0x0660, 0x066A))  # Arabic-Indic digits
    + list(range(0xFF10, 0xFF1A))  # full-width digits
    + [0x00B9, 0x00B2, 0x00B3] + list(range(0x2070, 0x207A))  # superscript digits
    + [ord(c) for c in "0123456789"]

def rune_class_entries(fn):
    out = []
    for cp in RUNE_CODEPOINTS:
        ch = chr(cp)
        out.append({"cp": cp, "input": ch, "expect": fn(ch)})
    return out


def is_space(ch: str) -> bool:
    return ch.isspace()


def is_word(ch: str) -> bool:
    return ch == "_" or ch.isalnum()


def is_digit(ch: str) -> bool:
    return ch.isdigit()


def is_decimal(ch: str) -> bool:
    return ch.isdecimal()


def is_upper(ch: str) -> bool:
    return ch.isupper()


def is_lower(ch: str) -> bool:
    return ch.islower()


LOWER_STRINGS = [
    "ABC", "abc", "\u0130STANBUL", "\u00df", "\u01c5", "\u03a3", "\u03a3\u03a3",
    "\u0391\u0393\u0399\u039f\u03a3", "\u039f\u0394\u03a5\u03a3\u03a3\u0395\u0399\u03a3",

# (text, char_index) -- char_index is a Python string index (code-point
# position); it is converted to a UTF-8 byte offset in build_wordboundary_goldens
# so the golden is directly usable from Go, which indexes strings by byte.
WORDBOUNDARY_CASES = [
    ("os.WriteFile", 0), ("os.WriteFile", 2), ("os.WriteFile", 3),
    ("xos.WriteFile", 1), (".os.WriteFile", 1), (" os.WriteFile ", 1),
    (" os.WriteFile ", 13), ("", 0), ("abc", 3), ("abc def", 3),
    ("abc_def", 3), ("caf\u00e9x", 4),
]


def build_wordboundary_goldens():
    out = []
    for text, char_index in WORDBOUNDARY_CASES:
        offset = len(text[:char_index].encode("utf-8"))
        expect = _boundary_at(text, char_index)
        out.append({"text": text, "offset": offset, "expect": expect})
    return out


def _boundary_at(text: str, pos: int) -> bool:
    import re
    before = text[pos - 1] if pos > 0 else ""
    after = text[pos] if pos < len(text) else ""
    before_is_word = bool(re.match(r"\w", before)) if before else False
    after_is_word = bool(re.match(r"\w", after)) if after else False
    return before_is_word != after_is_word


# Each entry is (prefix, selector) -- prefix is the text immediately BEFORE
# the point being tested; the full golden text is prefix + selector, and
# "offset" (a byte index) marks where the selector starts. "expect" is the
# POSITIVE semantics of pysem.PrecededByWordOrDot: True means the character
# immediately before offset IS a word char or '.'.
PRECEDED_CASES = [
    ("", "os.WriteFile"), ("x", "os.WriteFile"), (".", "os.WriteFile"),
    ("_", "os.WriteFile"), ("1", "os.WriteFile"), ("caf\u00e9", "os.WriteFile"),
    (" ", "os.WriteFile"), ("", ""),
]


def build_preceded_goldens():
    import re
    pattern = re.compile(r"(?<![\w.])")
    out = []
    for prefix, selector in PRECEDED_CASES:
        text = prefix + selector
        char_offset = len(prefix)
        offset = len(prefix.encode("utf-8"))
        # (?<![\w.]) matching at char_offset means NOT preceded; the golden's
        # positive-semantics "expect" is the logical negation.
        not_preceded = pattern.match(text, char_offset) is not None
        out.append({"text": text, "offset": offset, "expect": not not_preceded})
    return out


# Each entry is (selector, suffix) -- suffix is the text immediately AFTER
# the point being tested. "offset" marks where the selector ends / suffix
# begins. "expect" is the POSITIVE semantics of pysem.FollowedByWord: True
# means the character immediately at offset IS a word char.
FOLLOWED_CASES = [
    ("os.WriteFile", ""), ("os.WriteFile", "x"), ("os.WriteFile", "_"),
    ("os.WriteFile", "1"), ("os.WriteFile", "."), ("os.WriteFile", " "),
    ("os.WriteFile", "caf\u00e9"),
]


def build_followed_goldens():
    import re
    pattern = re.compile(r"(?![\w])")
    out = []
    for selector, suffix in FOLLOWED_CASES:
        text = selector + suffix
        char_offset = len(selector)
        offset = len(selector.encode("utf-8"))
        # (?![\w]) matching at char_offset means NOT followed by a word char;
        # the golden's positive-semantics "expect" is the logical negation.
        not_followed = pattern.match(text, char_offset) is not None
        out.append({"text": text, "offset": offset, "expect": not not_followed})
    return out


READTEXT_CASES = [
    ("plain.txt", "hello\nworld\n"),
    ("crlf.txt", "hello\r\nworld\r\n"),
    ("lone-cr.txt", "hello\rworld\r"),
    ("mixed.txt", "a\r\nb\rc\nd"),
]


def build_readtext_goldens(tmp_dir: Path):
    out = []
    for name, content in READTEXT_CASES:
        p = tmp_dir / name
        p.write_bytes(content.encode("utf-8"))
        # Python's universal-newline read_text translation.
        translated = content.replace("\r\n", "\n").replace("\r", "\n")
        out.append({"name": name, "raw_utf8_bytes": list(content.encode("utf-8")), "expect": translated})
    # invalid UTF-8 case
    invalid = tmp_dir / "invalid-utf8.bin"
    invalid_bytes = b"hello \xff\xfe world"
    invalid.write_bytes(invalid_bytes)
    out.append({"name": "invalid-utf8.bin", "raw_utf8_bytes": list(invalid_bytes), "expect": None, "invalid_utf8": True})
    return out


def build_pysem_goldens():

        "is_upper": rune_class_entries(is_upper),
        "is_lower": rune_class_entries(is_lower),
        "lower": build_lower_goldens(),
        "strip": build_strip_goldens(),
        "split_lines": build_splitlines_goldens(),
        "repr": build_repr_goldens(),
        "word_boundary": build_wordboundary_goldens(),
        "preceded_by_word_or_dot": build_preceded_goldens(),
        "followed_by_word": build_followed_goldens(),
        "read_text": build_readtext_goldens(tmp_dir),
    }
    import shutil
    shutil.rmtree(tmp_dir, ignore_errors=True)
    return data


def main():
    out_dir_gomask = ROOT / "internal" / "gomask" / "testdata"
    out_dir_pysem = ROOT / "internal" / "pysem" / "testdata"

    )

    pysem = build_pysem_goldens()
    (out_dir_pysem / "pysem_golden.json").write_text(

    print(f"python_version={PY_VERSION}")
    print(f"unidata_version={UNIDATA_VERSION}")
    print(f"masker entries: {len(masker)}")
    print("pysem golden keys:", list(pysem.keys()))


if __name__ == "__main__":
    main()

### 5.2 `gatecheck_gen_m1_writepath.py` (write-path goldens)

"""Transient golden generator for shipment 034-S / M1-T3 (write-path engine).

NOT committed (plan C-5 AC: "No .py file is added"). Run from repo root at

from __future__ import annotations

import json
import re
import subprocess
import sys
import traceback
from pathlib import Path

ROOT = Path.cwd()
sys.path.insert(0, str(ROOT / "scripts" / "lib"))
from gomask import mask_go_non_code  # noqa: E402

SELECTORS = [
    "os.WriteFile", "os.Create", "os.OpenFile", "os.Remove", "os.RemoveAll",
    "os.Rename", "os.Mkdir", "os.MkdirAll", "os.Symlink", "os.Chmod",
    "os.Truncate", "io.Copy", "sql.Open", "bbolt.Open",
    "os.CreateTemp", "os.MkdirTemp", "os.Link", "os.Chown", "os.Lchown",
    "os.Chtimes",
]
SELECTOR_RES = [
    (sel, re.compile(r'(?<![\w.])' + re.escape(sel) + r'(?![\w])'))
    for sel in SELECTORS
]


def scan_text(rel_path: str, text: str):
    findings = []
    masked = mask_go_non_code(text)
    for line_no, line in enumerate(masked.splitlines(), start=1):
        for sel, pattern in SELECTOR_RES:
            if pattern.search(line):
                findings.append(f"{rel_path}:{line_no}: write primitive {sel!r} found")
    return findings


def build_fixture_findings():
    fixture_dir = ROOT / "scripts" / "testdata" / "writepath"
    out = []
    for path in sorted(fixture_dir.glob("*.go")):
        text = path.read_text(encoding="utf-8")
        rel = path.relative_to(ROOT).as_posix()
        findings = scan_text(rel, text)
        out.append({
            "name": path.name,
            "expect_rejected": path.name.startswith("reject-"),
            "findings": findings,
        })
    return out


import os

BASH_ENV = dict(os.environ)
# Local dev-machine workaround: git-bash's PATH resolves the broken Windows
# Store "python3" app-execution-alias stub before the real interpreter (this
# machine has python.exe only, no python3.exe, so falling through to "python"
# never happens while the stub directory is present). Excise that one
# directory; not a repo behavior change, purely local subprocess env for
# golden capture.
_STUB_DIR = "WindowsApps"
BASH_ENV["PATH"] = ";".join(
    p for p in BASH_ENV.get("PATH", "").split(";") if _STUB_DIR not in p
)


def capture(cmd, cwd=None):
    proc = subprocess.run(cmd, cwd=cwd or ROOT, capture_output=True, text=False, env=BASH_ENV)
    # Windows python.exe's text-mode stdout/stderr apply universal-newline
    # translation (\n -> \r\n) purely because the interpreter is a native
    # Windows build; this is a local-capture artifact, not genuine engine
    # behavior. The real engine runs under Linux python3 in CI/production,
    # which never inserts \r. Normalize so the golden reflects the portable
    # (\n-only) behavior the Go port must match, not a local Windows quirk.

FILEBASED_CASES = {
    "crlf.go": (
        b'package w\r\n\r\nimport "os"\r\n\r\nfunc F() error {\r\n\treturn os.WriteFile("a", nil, 0o644)\r\n}\r\n'

def build_filebased_goldens(out_dir: Path):
    out_dir.mkdir(parents=True, exist_ok=True)
    results = []
    for name, raw in FILEBASED_CASES.items():
        (out_dir / name).write_bytes(raw)
        entry = {"name": name, "raw_bytes": list(raw)}
        try:
            text = raw.decode("utf-8")
            # universal newline translation mirrors Path.read_text's io layer
            translated = text.replace("\r\n", "\n").replace("\r", "\n")
            findings = scan_text(name, translated)
            entry["decode_error"] = False
            entry["translated_text"] = translated
            entry["findings"] = findings
        except UnicodeDecodeError as exc:
            entry["decode_error"] = True
            entry["error_repr"] = repr(exc)
        results.append(entry)
    return results

## 8. Pre-PR quality-gate fix: `filebased` reference fixtures vs. repo-wide `gofmt` (shipment-level closeout)

While re-running the full quality-gate sequence at 034-S shipment closeout (all 12 tasks done,
immediately before local review / PR creation), a genuine CI-breaking gap was found in the
`tools/gatecheck/internal/writepath/testdata/filebased/` reference fixtures added for the
M1-T3 golden capture (`bom.go`, `crlf.go`, `invalid-utf8.go`, `lone-cr.go`). These four files are
**not read by any test or production code at runtime** — `writepath_test.go`'s
`TestFilebased_ReadTextAndScan_MatchGolden` re-materializes the equivalent bytes from
`writepath_golden.json`'s `filebased[].raw_bytes` into a fresh `t.TempDir()` instead (confirmed
via `git grep` across the repo: the only other references to these filenames are descriptive
prose in this evidence file and `docs/memory/2026-09-30/...`). They exist purely as
human-readable byte-level documentation of what each golden case represents.

The repository's `.github/workflows/ci.yml` `lint` job's `gofmt` step runs
`out="$(gofmt -l .)"` (a plain recursive file-tree walk with no `testdata`-skip semantics — that
skip is a `go build`/`go vet`/`go test` package-discovery convention, not a `gofmt` one) under
GitHub Actions' default `bash -e` step shell. Three of the four fixtures are deliberately
malformed at the byte level to exercise `pysem.ReadText`'s edge-case handling:
`invalid-utf8.go` (invalid UTF-8) and `lone-cr.go` (a bare `\r` with no matching `\n`) do not
parse as Go at all, so `gofmt -l .` exits 2 on them (confirmed locally: `gofmt -l .` against the
four-file directory reproduces `illegal UTF-8 encoding` / `expected ';', found 'import'` and a
non-zero process exit); under `bash -e`, `out="$(gofmt -l .)"` propagates that non-zero exit and
fails the step *before* it ever reaches its own `if [ -n "$out" ]` check. `bom.go` parses (Go's
scanner strips a leading BOM per the language spec) but `gofmt` still flags it as needing
reformatting (it strips the BOM), so it too would have been listed by `-l` even absent the other
two. `crlf.go` is unaffected — `gofmt` preserves a file's dominant line-ending style, and a
CRLF-consistent file is otherwise valid Go, so it was already `gofmt`-clean.

This is a defect introduced by 034-S's own earlier fixture work (M1-T3), not a pre-existing
repository condition, and it would fail CI's `lint` job on push — fixing it is completing this
shipment's own work to a CI-green state, not new scope. Verified via `git grep`, `git archive`
(exact committed-blob bytes; the on-disk working copies of many of this session's newly authored
`.go` files carry a stray Windows-CRLF checkout artifact — `.gitattributes`' `eol=lf` normalizes
what git stores, not necessarily what's currently sitting on disk locally — so the check must run
against archived/committed content, not the raw working tree, to avoid a false positive) that
no other repository file references these four fixtures by path, so the safe, minimal,
zero-behavior-change fix was a rename off the `.go` extension (`git mv` to `*.go.txt`,
content byte-for-byte unchanged) so `gofmt`'s file-tree walk no longer visits them, while
`writepath_test.go` and `writepath_golden.json` (which never referenced these paths) are
untouched. Re-verified via `git archive HEAD | tar -x` into a scratch directory (bypassing the
working-tree CRLF artifact) that `gofmt -l .` is now clean across the entire committed tree,
`go build ./...` / `go vet ./...` / `go test ./...` remain green, and `git grep` confirms zero
remaining path references to the old `.go`-suffixed names outside this evidence file's own
descriptive prose (now updated above) and the untouched, purely-historical
`docs/memory/2026-09-30/...` checkpoint.
