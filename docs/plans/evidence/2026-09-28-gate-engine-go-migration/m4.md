# M4 gate-engine Python retirement — evidence

This document records the evidence for Unit M4 (feature `047-F`, shipment `037-S`). M4 removes
the last gate-engine Python from the repository after M1 to M3 ported every engine to
`tools/gatecheck`. It deletes the shared masker module, the extracted retired-architecture
module, and their unit-test suite. It removes the two `lint`-job CI steps that ran that suite and
rewrites the wrapper headers that still describe Python. The `topology-check` job's
`setup-python` step is out of scope and stays byte-identical: it installs the `autoharness`
Python package, not a gate engine.

## 4. M4-T3 retirement assertions (red first, Principle II)

`tools/gatecheck/ciwiring_retire_test.go` adds the three retirement assertions:

* (i) Outside job `topology-check`, no `uses:` line installs Python through
  `actions/setup-python`. The match is case-insensitive and accepts single- or double-quoted
  keys and values.
* (ii) Outside job `topology-check`, no `run:` line invokes the interpreter. A quoted `'run':` or
  `"run":` key counts the same as a bare one. This covers inline,
  list-item, `|` and `>` forms. The interpreter forms include versioned, absolute, Windows
  (`python.exe`, `pythonw.exe`, backslash paths) and `py` / `py.exe` launcher forms. The same assertion also
  rejects a step-level `shell:` key (bare or quoted) or a `defaults.run.shell` key that selects the interpreter,
  including a custom shell template such as `python3 {0}`.
* (iii) `git ls-files -z -- 'scripts/*.py' 'tools/*.py'` is empty.

Implementation rules:

* Patterns are built from string fragments so the test file never matches itself.
* The pathspec has no `:(glob)` magic, so `*` crosses `/`. A comment in the test records this.
* Git calls use the §6 isolation environment. They also remove the four `GIT_*_PATHSPECS`
  variables.

Supporting tests are green:

* `TestCIWiringRetire_MutatedInputsAreRed` builds a synthetic workflow that starts green and
  has 35 injected red cases covering assertions (i) and (ii), including seven YAML flow-style
  steps. Its ten green cases are non-invocations, such as a hyphenated `--python-version` flag,
  a longer word and a step name, plus braces that are not flow mappings: a `${{ }}` expression, a
  quoted scalar, a comment and shell braces in a `run: |` body. Assertions (i) and (ii) both
  reject any YAML flow-style mapping outside `topology-check`. The case counts here are current
  as of Copilot round 11.
* `TestCIWiringRetire_TrackedPythonInTempRepoIsRed` uses a temp repo containing:
  * a top-level `scripts/x.py`
  * a nested `scripts/a/b.py`
  * a nested `tools/c/d.py`
  * an out-of-scope `docs/e.py`
  * a non-Python `scripts/keep.sh`

  Exactly the three in-scope files are reported, which also proves argv is not shell-globbed.
* `TestCIWiringRetire_TopologyExemptionIsReal` renames `topology-check` and confirms that (i)
  then flags that job's own pinned `setup-python` step.

## 8. M4-T9 consolidated parity

### 8.1 Method

* **Snapshots.** Each compared commit was extracted with `git archive <sha>` into an ignored
  scratch directory under `logs/parity/`. The extracted tree was then `git init`-ed and
  committed with an `origin` remote, which satisfies the wrappers' checkout precondition. No
  `git worktree` was used (P-016).
* **Runtime.** Every wrapper ran under Git-Bash (`C:\Program Files\Git\bin\bash.exe`) with Go
  1.26.5. For the Python-era trees, `python3` resolved to Python 3.14.3.
* **Modes.** Each gate ran in every mode that needs neither a network nor a PR context, plus
  the usage paths:

  | Gate | Modes |
