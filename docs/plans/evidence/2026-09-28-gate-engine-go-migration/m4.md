# M4 gate-engine Python retirement — evidence

This document records the evidence for Unit M4 (feature `047-F`, shipment `037-S`). M4 removes
the last gate-engine Python from the repository after M1 to M3 ported every engine to
`tools/gatecheck`. It deletes the shared masker module, the extracted retired-architecture
module, and their unit-test suite. It removes the two `lint`-job CI steps that ran that suite and
rewrites the wrapper headers that still describe Python. The `topology-check` job's
`setup-python` step is out of scope and stays byte-identical: it installs the `autoharness`
Python package, not a gate engine.

## 3. M4-T2 CI-wiring and wrapper-text tests (green on live, red on mutations)

`tools/gatecheck/ciwiring_test.go` reads `ci.yml` as text, with no YAML library. It finds each job
by its two-space-indented key and each step by its `name:` text, never by line number. It
asserts:

* `lint`, `gitignore-append-only` and `merge-strategy` each have a step named `Set up Go` that
  comes before every gate and self-test step.
* Each gate step runs its wrapper. The advisory `continue-on-error` expressions are intact.
* The self-test and self-test-integrity steps carry no `continue-on-error`.
* `topology-check` keeps its SHA-pinned `setup-python` and at least two `--require-hashes` pip
  steps.

`tools/gatecheck/wrapper_text_test.go` holds the four new wrapper-text tests named in §2.

Each mutation case below must produce at least one problem. Each case also checks that the
mutation actually changed the text:

* `TestCIWiring_MutatedInputsAreRed`, 13 cases:
  * removed steps: a lint self-test, lint `Set up Go`, the merge-strategy gate, and a
    `topology-check` hash-pinned pip step
  * reordered steps: `Set up Go` moved after a gate in each of the three jobs
  * `continue-on-error` added to two self-test steps
  * an inverted advisory expression
  * a wrong wrapper path
  * a changed pin
  * a renamed job
* The wrapper-text tests inject:
  * an interpreter call, a heredoc, an engine module reference, and an `ENGINE=` variable
  * a removed decision string
  * a removed build, source or invoke dispatch line

A comment-only mention is allowed and stays green.

## 4. M4-T3 retirement assertions (red first, Principle II)

`tools/gatecheck/ciwiring_retire_test.go` adds the three retirement assertions:

* (i) Outside job `topology-check`, no line installs Python through `actions/setup-python`.
* (ii) Outside job `topology-check`, no `run:` line invokes the interpreter. This covers inline,
  list-item, `|` and `>` forms.
* (iii) `git ls-files -z -- 'scripts/*.py' 'tools/*.py'` is empty.

Implementation rules:

* Patterns are built from string fragments so the test file never matches itself.
* The pathspec has no `:(glob)` magic, so `*` crosses `/`. A comment in the test records this.
* Git calls use the §6 isolation environment. They also remove the four `GIT_*_PATHSPECS`
  variables.

Supporting tests are green:

* `TestCIWiringRetire_MutatedInputsAreRed` builds a synthetic workflow that starts green and
  has six injected red cases. Three non-invocations stay green: a hyphenated
  `--python-version` flag, a longer word, and a step name.
* `TestCIWiringRetire_TrackedPythonInTempRepoIsRed` uses a temp repo containing:
  * a top-level `scripts/x.py`
  * a nested `scripts/a/b.py`
  * a nested `tools/c/d.py`
  * an out-of-scope `docs/e.py`
  * a non-Python `scripts/keep.sh`

  Exactly the three in-scope files are reported, which also proves argv is not shell-globbed.
* `TestCIWiringRetire_TopologyExemptionIsReal` renames `topology-check` and confirms that (i)
  then flags that job's own pinned `setup-python` step.
