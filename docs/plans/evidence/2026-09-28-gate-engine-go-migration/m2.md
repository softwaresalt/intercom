1. Bash invocations that need to reach the Go toolchain use
   `C:\Program Files\Git\bin\bash.exe` explicitly (plain `bash` on `PATH` on this machine resolves

   so the wrapper's `python`/`python3` interpreter search falls through to the real
   `C:\Python\Python314\python.exe` instead of the Windows Store alias stub.

   engine only ever runs under Linux `python3` in CI; all captured stream bytes below are
   normalized `\r\n` → `\n` before being written into the golden or compared.

None of these three items changed any *logical* output (selectors matched, exit codes, assertion
names/order, PASS/FAIL wording) — only which interpreter answered the call and what raw bytes a
Windows-hosted pipe carried.

#### 3.2.1 Why TOML engine "agreement" is verdict-only, not text-equal

`tomllib`'s own finding-report path (`report_toml_key`) has no line number (TOML tables don't
carry Python source-line coordinates the way the fallback lexer's manual scan does); the
fallback engine's finding text always includes one. Literal string equality between the two
engines' finding text would therefore never hold even when both engines correctly agree that a
fixture is clean or correctly agree on *which* keys are forbidden. This mirrors production:
`run_fixture_self_test` checks each engine independently against the *same* manifest expectation
(clean vs. reject), never compares the two engines' output to each other. The Go port's
`tomlprimary_test.go`/`tomlfallback_test.go` follow the same pattern; only `select_test.go`-style
dual-engine-agreement tests compare the two engines' **verdicts**, never their prose.

```python
"""Transient golden generator for shipment 035-S / M2-T1 (feature 045-F).

NOT committed to the repository (plan C-5 / M2-T1 AC: "No .py file is
added"). Run from the repo root at the parent commit of the M2 golden
capture:

    python C:\\Users\\Public\\gatecheck_gen_m2.py

Writes:
    tools/gatecheck/internal/retiredarch/testdata/retiredarch_golden.json

This script is deleted after the goldens are captured; its full text is
recorded verbatim in
docs/plans/evidence/2026-09-28-gate-engine-go-migration/m2.md.
"""
from __future__ import annotations

import json
import os
import subprocess
import sys
import unicodedata
from pathlib import Path

ROOT = Path.cwd()
sys.path.insert(0, str(ROOT / "scripts" / "lib"))
import retired_arch as ra  # noqa: E402
import gomask  # noqa: E402

PY_VERSION = sys.version.split()[0]
UNIDATA_VERSION = unicodedata.unidata_version
GO_UNICODE_VERSION = "15.0.0"  # recorded per C-4; this generator runs no Go.

ROOT_POSIX = ROOT.as_posix()
ROOT_PLACEHOLDER = "\u0001REPOROOT\u0001"


def normalize_findings(findings):
    """retired_arch.py's finding strings embed path.as_posix() of an
    ABSOLUTE Path (root / rel_path, where root comes from
    resolve_repo_root() -> `git rev-parse --show-toplevel`) -- unlike
    write-path's engine, which formats findings against a caller-supplied
    repo-relative string. This is a genuine, deliberate fidelity point (not
    a normalization bug): the Go port must also embed an absolute,
    forward-slash path so its finding text matches byte for byte in
    production. For portability across machines/CI, this generator
    replaces the CAPTURE MACHINE'S absolute repo root with a placeholder
    token; the Go golden test substitutes its own repoRoot(t) back in
    before comparing.
    """
    return [f.replace(ROOT_POSIX, ROOT_PLACEHOLDER) for f in findings]

BASH = r"C:\Program Files\Git\bin\bash.exe"

BASH_ENV = dict(os.environ)
_STUB_DIR = "WindowsApps"
BASH_ENV["PATH"] = ";".join(
    p for p in BASH_ENV.get("PATH", "").split(";") if _STUB_DIR not in p
)


def capture(cmd, cwd=None):
    proc = subprocess.run(cmd, cwd=cwd or ROOT, capture_output=True, text=False, env=BASH_ENV)
    return {
        "cmd": cmd if isinstance(cmd, list) else [cmd],
        "cwd": str(cwd) if cwd else ".",
        "stdout": proc.stdout.decode("utf-8", errors="replace").replace("\r\n", "\n"),
        "stderr": proc.stderr.decode("utf-8", errors="replace").replace("\r\n", "\n"),
        "exit_code": proc.returncode,
    }


def assertions_from_stdout(stdout: str):
    """Extract ordered (name, outcome) pairs from PASS/FAIL-prefixed lines."""
    out = []
    for line in stdout.split("\n"):
        if line.startswith("PASS "):
            rest = line[len("PASS "):]
            name = rest.split(":", 1)[0]
            out.append({"name": name, "outcome": "PASS"})
        elif line.startswith("FAIL "):
            rest = line[len("FAIL "):]
            name = rest.split(":", 1)[0]
            out.append({"name": name, "outcome": "FAIL"})
    return out


# ---------------------------------------------------------------------------
# Go fixture findings (retiredgo/**, retiredgo-differential/**), both masked
# (mask=True, the real production path) and unmasked (mask=False, the
# go-differential suite's engine_override path) for every fixture.
# ---------------------------------------------------------------------------

def build_go_fixture_findings():
    out = []
    for glob_dir, glob_pat in (
        ("retiredgo", "*.go"),
        ("retiredgo-differential", "*.go"),
    ):
        fixture_dir = ROOT / "scripts" / "testdata" / glob_dir
        for path in sorted(fixture_dir.glob(glob_pat), key=lambda p: p.as_posix()):
            masked_findings = normalize_findings(ra.scan_go(path, mask=True))
            unmasked_findings = normalize_findings(ra.scan_go(path, mask=False))
            out.append({
                "name": f"{glob_dir}/{path.name}",
                "masked_findings": masked_findings,
                "unmasked_findings": unmasked_findings,
            })
    return out


# ---------------------------------------------------------------------------
# TOML fixture findings under both engines (tomllib + fallback), for every
# scripts/testdata/retired-*.toml fixture.
# ---------------------------------------------------------------------------

def build_toml_fixture_findings():
    out = []
    testdata_dir = ROOT / "scripts" / "testdata"
    for path in sorted(testdata_dir.glob("retired-*.toml"), key=lambda p: p.as_posix()):
        tomllib_findings = normalize_findings(ra.scan_toml_with_tomllib(path))
        fallback_findings = normalize_findings(ra.scan_toml_with_fallback(path))
        out.append({
            "name": path.name,
            "tomllib_findings": tomllib_findings,
            "fallback_findings": fallback_findings,
            # "agree" is VERDICT agreement (rejected vs clean), not finding-text
            # equality: the two engines format finding prose differently by
            # design (tomllib's report_toml_key has no line number; the
            # fallback's finding text does), so literal string equality would
            # never hold even when both engines correctly reject the same
            # fixture. This mirrors the actual enforcement mechanism in
            # run_fixture_self_test: both engines are checked independently
            # against the SAME manifest expectation, which transitively
            # proves verdict agreement without ever comparing finding text.
            "agree": bool(tomllib_findings) == bool(fallback_findings),
        })
    return out


# ---------------------------------------------------------------------------
# split_identifier / segment_whole goldens: every fixture identifier plus the
# forbidden_parts vocabulary, plus explicit Unicode identifier cases.
# ---------------------------------------------------------------------------

def collect_fixture_identifiers():
    idents = set()
    for glob_dir, glob_pat in (
        ("retiredgo", "*.go"),
        ("retiredgo-differential", "*.go"),
    ):
        fixture_dir = ROOT / "scripts" / "testdata" / glob_dir
        for path in sorted(fixture_dir.glob(glob_pat)):
            text = path.read_text(encoding="utf-8")
            masked = gomask.mask_go_non_code(text)
            for m in ra.go_identifier_re.finditer(masked):
                idents.add(m.group(0))
    for word in ra._VOCAB_WORDS:
        idents.add(word)
    return sorted(idents)


UNICODE_IDENT_CASES = [
    "channel\u0130d",       # capital dotted I (İ) inline
    "\u0130channelID",      # İ prefix
    "channel\uFF29d",       # full-width Latin capital letter I (\uFF29)
    "team\uFF29ds",         # full-width I inside plural
    "socket\u0130mode",
]


def build_ident_goldens():
    names = collect_fixture_identifiers() + UNICODE_IDENT_CASES
    out = []
    for name in names:
        parts = ra.split_identifier(name)
        out.append({
            "name": name,
            "split_identifier": parts,
            # segment_whole is captured both on the identifier's own lowered
            # whole text AND per-component (the real call pattern inside
            # matches_forbidden_concat, which iterates split_identifier's
            # output components) so the Go port can be checked against both
            # shapes.
            "segment_whole_whole": ra.segment_whole(name.lower()),
            "segment_whole_per_component": [ra.segment_whole(p) for p in parts],
        })
    return out


# ---------------------------------------------------------------------------
# New inline TOML goldens (M2-T1 AC list). Captured under both engines plus
# the BOM fail-closed-reject and ED-6 cases.
# ---------------------------------------------------------------------------

INLINE_TOML_CASES = {
    # Legal "reopened table" shape: [a.b] implicitly creates parent table a;
    # [a] later explicitly reopens/extends it with a sibling key. The literal
    # AC shape "[a] ... [a.b] ... [a]" (a plain header repeated three times)
    # is NOT legal TOML (redeclaring [a] after it was already explicitly
    # declared is a hard parse error under both tomllib and BurntSushi -
    # verified empirically during staging); this is the nearest legal analog.
    "reopened-table": "[a.b]\nx = 1\n\n[a]\ny = 2\n",
    "dotted-key-3segment": "a.b.c = 1\n",
    "array-of-tables-differing-key-order": (
        "[[t]]\nx = 1\ny = 2\n\n[[t]]\ny = 3\nx = 4\n"
    ),
    "inline-tables-in-array-differing-order-and-keyset": (
        "arr = [ { x = 1, y = 2 }, { y = 3, z = 4 } ]\n"
    ),
    "nested-array-of-tables-plus-subtable": (
        "[[t]]\n"
        "name = \"one\"\n\n"
        "  [[t.u]]\n"
        "  a = 1\n\n"
        "  [[t.u]]\n"
        "  a = 2\n\n"
        "  [t.sub]\n"
        "  s = 1\n\n"
        "[[t]]\n"
        "name = \"two\"\n\n"
        "  [[t.u]]\n"
        "  a = 3\n\n"
        "  [t.sub]\n"
        "  s = 2\n"
    ),
    "quoted-key-with-dot": "[\"a.b\"]\nx = 1\n",
    # ED-6: valid TOML 1.1 (newline inside an inline table), invalid TOML 1.0.
    # Go (BurntSushi v1.6.0) accepts; Python (tomllib, TOML 1.0) rejects.
    "ed6-newline-in-inline-table": "arr = { x = 1,\n y = 2 }\n",
    # forbidden-token content threaded through the new shapes, so the dual
    # engine + primary walker tests have at least one case per new shape that
    # actually produces a finding.
    "array-of-tables-forbidden-token": (
        "[[t]]\nchannel_id = 1\n\n[[t]]\nteam_id = 2\n"
    ),
    "nested-aot-forbidden-token": (
        "[[t]]\nname = \"one\"\n\n  [[t.u]]\n  socket_mode = 1\n"
    ),
    "quoted-key-with-dot-forbidden-token": "[\"channel.id\"]\nx = 1\n",
}

# BOM case is handled separately: Python fail-closed rejects (confirmed:
# TOMLDecodeError('Invalid statement (at line 1, column 1)')) because
# read_text(encoding='utf-8') does NOT strip a BOM (unlike utf-8-sig), so
# tomllib sees the literal U+FEFF character. This is recorded as raw bytes so
# the Go golden test can materialize the same file.
BOM_TOML_BYTES = "\ufeff[a]\nx = 1\n".encode("utf-8")


def build_inline_toml_goldens(materialize_dir: Path):
    materialize_dir.mkdir(parents=True, exist_ok=True)
    out = {}
    for name, text in INLINE_TOML_CASES.items():
        path = materialize_dir / f"{name}.toml"
        path.write_text(text, encoding="utf-8")
        tomllib_findings = normalize_findings(ra.scan_toml_with_tomllib(path))
        fallback_findings = normalize_findings(ra.scan_toml_with_fallback(path))
        out[name] = {
            "text": text,
            "tomllib_findings": tomllib_findings,
            "fallback_findings": fallback_findings,
            "agree": bool(tomllib_findings) == bool(fallback_findings),
        }

    bom_path = materialize_dir / "bom-case.toml"
    bom_path.write_bytes(BOM_TOML_BYTES)
    bom_tomllib = normalize_findings(ra.scan_toml_with_tomllib(bom_path))
    bom_fallback = normalize_findings(ra.scan_toml_with_fallback(bom_path))
    out["leading-utf8-bom"] = {
        "raw_bytes": list(BOM_TOML_BYTES),
        "tomllib_findings": bom_tomllib,
        "fallback_findings": bom_fallback,
        "agree": bool(bom_tomllib) == bool(bom_fallback),
    }
    return out


# ---------------------------------------------------------------------------
# Stream captures: --self-test / --self-test-integrity / unknown-mode via the
# real wrapper script (subprocess), exactly like the M1 generator's pattern.
# ---------------------------------------------------------------------------

def build_stream_captures():
    wrapper = "scripts/check-retired-architecture.sh"
    modes = {
        "self_test": capture([BASH, wrapper, "--self-test"]),
        "self_test_integrity": capture([BASH, wrapper, "--self-test-integrity"]),
        "unknown_mode": capture([BASH, wrapper, "--bogus"]),
        "repo": capture([BASH, wrapper]),
    }
    for key in ("self_test", "self_test_integrity", "unknown_mode", "repo"):
        modes[key]["assertions"] = assertions_from_stdout(modes[key]["stdout"])
    return modes


# ---------------------------------------------------------------------------
# Repo-mode verdict + selected path set: evidence only (normal cwd,
# subdirectory cwd, absolute path from inside another repo).
# ---------------------------------------------------------------------------

def build_repo_mode_evidence(tmp_repo_dir: Path):
    wrapper_abs = (ROOT / "scripts" / "check-retired-architecture.sh").as_posix()
    out = {}
    out["normal_cwd"] = capture([BASH, "scripts/check-retired-architecture.sh"])
    out["subdirectory_cwd"] = capture([BASH, wrapper_abs], cwd=ROOT / "internal")

    tmp_repo_dir.mkdir(parents=True, exist_ok=True)
    subprocess.run(["git", "init", "-q"], cwd=tmp_repo_dir, check=True)
    out["another_repo_cwd"] = capture([BASH, wrapper_abs], cwd=tmp_repo_dir)

    selection = ra.select_repo_paths(ROOT)
    out["selected_path_set"] = selection
    out["selected_path_count"] = len(selection)
    return out


def main():
    testdata_dir = ROOT / "tools" / "gatecheck" / "internal" / "retiredarch" / "testdata"
    testdata_dir.mkdir(parents=True, exist_ok=True)
    inline_dir = testdata_dir / "_inline_toml_materialized"

    golden = {
        "python_version": PY_VERSION,
        "unidata_version": UNIDATA_VERSION,
        "go_unicode_version": GO_UNICODE_VERSION,
        "root_placeholder": ROOT_PLACEHOLDER,
        "vocab_words": ra._VOCAB_WORDS,
        "forbidden_parts_order": list(ra.forbidden_parts.keys()),
        "forbidden_parts": ra.forbidden_parts,
        "go_fixture_findings": build_go_fixture_findings(),
        "toml_fixture_findings": build_toml_fixture_findings(),
        "ident_goldens": build_ident_goldens(),
        "inline_toml_goldens": build_inline_toml_goldens(inline_dir),
        "stream_captures": build_stream_captures(),
        "repo_mode_evidence": build_repo_mode_evidence(Path(r"C:\Users\Public\gatecheck_m2_another_repo")),
    }

    out_path = testdata_dir / "retiredarch_golden.json"
    out_path.write_text(json.dumps(golden, indent=2, sort_keys=False), encoding="utf-8")
    print(f"wrote {out_path}")


if __name__ == "__main__":
    main()
```

## 4. M2-T2 — `ident.go`

Ports `split_camel_acronym`, `split_identifier`, `segment_whole`, and the exact-match helper
underneath it (Python's own name for the latter is `segment_whole`'s single internal branch, not
a separately named function — there is no `_segment_whole_exact` in the actual source; the
plan's task list uses a slightly generalized name for it, and the SOURCE's actual shape (one
function, `segment_whole`, with an early-return exact-vocabulary-hit branch followed by a
greedy-longest-prefix loop) was used as ground truth per the task instructions), built entirely
on `pysem.Lower`, `pysem.IsUpper`, `pysem.IsWord`, and `pysem.WordBoundary` rather than Go's
`unicode`/`strings` packages directly. `_VOCAB_WORDS` is ported in its exact source order.

`ident_test.go` asserts, for every one of the 100% of golden `ident_goldens` entries (fixture
identifiers + `_VOCAB_WORDS` + the 5 explicit Unicode cases), that `splitIdentifier` and
`segmentWhole` (both the whole-identifier call and the per-component calls) match the Python
golden exactly. All entries pass, including the Unicode cases:

* `channelİd`, `İchannelID`, `socketİmode` (capital dotted I, `U+0130`) — Python's `str.lower()`
  maps `İ` to `i̇` (two code points: ASCII `i` + combining dot above, `U+0307`), which changes
  where `pysem.IsWord` reports a boundary versus a naive Go `unicode.ToLower`; `pysem.Lower` was
  required to reproduce this exactly (this is the same Final-Sigma/`İ` pitfall M1's `pysem`
  package was built to solve).

## 7. M2-T5 — `tomlprimary.go` (the ordering algorithm)

### 7.1 The problem (plan C-6)

Python's `tomllib.loads()` returns an ordinary `dict`, which preserves first-insertion order for
iteration — so `walk_toml_value`'s recursive dict/list walk visits siblings and array elements in
the exact order they appeared in the source document. Go's `encoding/json`-style decode into
`map[string]interface{}` has **no** such ordering guarantee, and BurntSushi/toml decodes into a
plain Go map for exactly this reason. BurntSushi's `toml.MetaData.Keys()` *does* return every key
path in source-declaration order, but as a **flat list**, not a tree, and its exact
entry-per-key/entry-per-array-element shape (including a synthetic self-entry for a table right
before its first field, and one *per-element* self-entry list for arrays of tables) has to be
walked in lockstep with the decoded tree to recover sibling and array-element order without ever
sorting or guessing.

### 7.2 The lockstep-cursor algorithm

Implemented as `tomlCursor` (a single, forward-only index into the flat `[]toml.Key` list) plus
three mutually-recursive walkers, `walkTable`, `walkArrayOfTables`, and `walkArray`:

* `tomlCursor.peekChild(prefix)` looks at the *next unconsumed* key in the flat list and reports
  whether it is an **exact** match for `prefix` (a table/array-of-tables self-entry, e.g. `[a]`
  reopening after `[a.b]`) or a **strict extension** of `prefix` by exactly one more segment (an
  ordinary child key or nested-table entry).
* `walkTable` loops, consuming one cursor entry per call, until an `opened` set (scoped to *this*
  table invocation only, not global) has recorded every field name the *decoded* Go map itself
  reports for this table (`len(opened) < len(table)` bounds the loop) — this correctly stops each
  table's own walk exactly when its own fields are exhausted, including when array-of-tables /
  inline-table-in-array elements interleave additional entries for *nested* structures in between
  this table's own top-level keys.
* `walkArrayOfTables` restarts a fresh `opened` cursor scope *per element*, consuming that
  element's own self-entry first (the "reopened element" case every array-of-tables element after
  the first requires, since BurntSushi's flat key list gives each `[[t]]` occurrence its own
  self-entry at the array index) before recursing into that element's own `walkTable`.
* `walkArray` (a plain array, not array-of-tables) walks a `[]interface{}` positionally — plain
  array element order needs no ordering recovery (Go slices already preserve it from decode), but
  *inline tables inside* a plain array (e.g. `arr = [ {x=1,y=2}, {y=3,z=4} ]`) still need the
  cursor to recover per-element inline-table key order, which BurntSushi's `Keys()` does still
  emit per positional array index.

This algorithm was derived empirically against BurntSushi/toml v1.6.0 by dumping
`MetaData.Keys()` for a battery of shapes — reopened tables via dotted-header continuation,
arrays of tables, nested arrays of tables, inline tables inside plain arrays with differing key
sets, and quoted keys containing a literal `.` — and is recorded as inline code commentary
directly above `tomlCursor`'s definition and above each walker in `tomlprimary.go`.

**No TOML shape encountered (fixture corpus + all 9 new inline shapes) produced an
irreproducible order** — this was not a stop condition. Every fixture and every new inline case's
primary-engine order was verified to match the Python golden **in order** (element-for-element,
not just set-equal), including all 4 of the newly-authored order-scrambling cases (differing
array-of-tables element key order, differing-order-and-differing-keyset inline tables in an
array, nested arrays of tables with an interleaved sub-table, and a quoted dotted key). **Correction
(F-3, see §7.5): this claim was NOT true for the reopened-table shape at the time it was
originally written** — that shape's only test assertion was a vacuous empty-findings-list
equality (`reopened-table`'s golden entry is `tomllib_findings: []`/`fallback_findings: []`),
which cannot distinguish "every field was visited and none matched" from "a field was silently
skipped and never checked" (see F-1's root-cause trace in §7.5). The claim is corrected here to:
every fixture and inline case's order was verified element-for-element **except** the
reopened-table shape, whose only assertion was clean-vs-clean equality; §7.5 closes that gap with
a real forbidden-token variant, after which the "verified in order, element-for-element" claim

### 7.3 BOM parity (C-6)

BurntSushi/toml v1.6.0's `parse.go` (lines 43–50 in the vendored module source) explicitly strips
a leading UTF-8 BOM (`\xef\xbb\xbf`) before lexing — i.e. it silently **accepts** a BOM-prefixed

line 1, column 1. `scanTomlPrimary` therefore explicitly rejects a leading `U+FEFF` **before**
ever calling `toml.Decode`, reproducing Python's fail-closed behavior rather than BurntSushi's
silent-accept. Confirmed via the golden's `leading-utf8-bom` inline case: both engines reject
(non-empty findings); per ED-4, only the reject **verdict** is asserted equal, not the literal
error prose (`tomlprimary_test.go`'s `bomCaseName` branch calls a verdict-only
`assertFailClosedReject` helper rather than `reflect.DeepEqual`).

### 7.5 Post-review remediation: F-1 (`walkTable` reopened-table false-clean) and F-3 (evidence overclaim)

**Source:** `docs/closure/2026-09-30-gate-engine-m2-retired-arch-adversarial-review.md`, findings
F-1 (CRITICAL) and F-3 (MAJOR, corroborated by F-1). Also closes F-4 (tautological
`reopened-table.toml` golden) and F-5 (silent `nil` return on cursor/table mismatch) as identical
root-cause side effects, per the review's own non-goal instructions — no separate fixture or
hardening was added for those two beyond what this section describes.

**The bug.** `walkTable`'s per-table loop asked `cursor.peekChild(prefix)` for the next child and,
on `ok=false`, unconditionally returned a clean `nil` result — even when `len(opened) <
len(table)` still held. `peekChild` returns `ok=false` not only at genuine end-of-table but also
when the very next cursor entry is an **exact self-entry** for the table's own prefix, which is
exactly what BurntSushi's `MetaData.Keys()` emits when a plain (non-array) table is **reopened**
later in the document via a second `[header]` line (e.g. `[a.b]` ... `[a]` continuing to add
siblings of `b` under `a`). The reopened header's newly-added field(s) were therefore never
visited or checked against `matchesForbiddenParts` — a silent false-clean on a common, entirely
legal TOML idiom. The shipped `reopened-table.toml` fixture (`[a.b]\nx = 1\n\n[a]\ny = 2\n`) never
caught this because its reopened field `y` is an inert key; the golden's `tomllib_findings`/
`fallback_findings` for that case are both `[]`, so the equality assertion in
`TestScanTomlPrimary_MatchesGolden_Inline` passed **vacuously** whether or not `y` was actually
walked (F-4). This is also why the §7.2 claim that every new inline shape's order was verified
"in order, element-for-element" was inaccurate for this one shape (F-3): the only assertion in
place for it was incapable of detecting the skip.

**The fix.** In `walkTable`, when `peekChild` returns `ok=false` but `len(opened) < len(table)`
still holds, the loop now checks `cursor.peekSelf(prefix)` (the same primitive
`walkArrayOfTables` already used for its own analogous reopened-element case) before giving up:
if true, it consumes that self-entry and `continue`s the loop so the reopened header's remaining
fields are still discovered and checked. Only `len(opened) == len(table)` now produces a clean
return. As belt-and-suspenders hardening (closing F-5), any other case where `peekChild` fails and
`peekSelf` is also false, while fields remain unvisited, now returns a
`fmt.Errorf("retiredarch: TOML cursor desync: ...")` invariant-violation error (this file's
existing fail-closed style for cursor/table mismatches) instead of a silent `nil`.

### 12.1 Post-review remediation: F-2 (`loadFixtureManifest` value-type narrowing) and F-6 (`::error::` prefix on a bare-message reject)

**Source:** `docs/closure/2026-09-30-gate-engine-m2-retired-arch-adversarial-review.md`, findings
F-2 (MINOR) and F-6 (MINOR, same manifest-shape-reject code path).

**F-2 bug.** `loadFixtureManifest` unmarshalled directly into `map[string]string`, so *any*
non-string JSON value anywhere in the manifest (not just a non-object top level) hard-rejected
the whole manifest with the generic `"invalid fixture manifest shape"` error. Python's
`load_fixture_manifest` only requires `isinstance(data, dict)` at the top level and defers a
non-string value to the later per-fixture `unknown expectation {value!r} in <manifest>` failure
inside `run_fixture_self_test` — a materially different stdout/stderr byte stream under this
repo's C-5 ordered-byte-comparison discipline. A related ambiguity: an explicit manifest value of
`""` and an absent key both collapsed into the same `""` sentinel in `sortedNonEmptyKeys`, whereas
Python's `manifest.get(name)` (`None` vs `''`) keeps them distinguishable.

**F-2 fix.** `loadFixtureManifest` now decodes into `map[string]interface{}` (via a
`json.Number`-preserving `json.Decoder`, rejecting trailing top-level content the same way
`json.Unmarshal` would) and only hard-rejects a genuinely non-object top level. A new
`manifestExpectation` type (`isNone`/`isString`/`other` fields) and `lookupExpectation` helper
carry each fixture's expectation through `runFixtureSelfTest` as Python's `manifest.get(name)`
would, so a present-but-non-string value reaches the same `"unknown expectation %s in %s"`
failure text (via a new `reprJSONValue`/`manifestExpectation.repr()` Python-repr-equivalent
renderer) instead of a load-time hard reject, and an absent key stays distinguishable from an
explicit empty string in the renamed `sortedKeys` helper (which no longer needs an
exclude-empty-string sentinel, since only genuine string-typed expectations are inserted into
that set now).

**F-6 bug.** The manifest-shape hard-reject error was surfaced to stderr as
`"::error::%v\n"`, but Python's `raise SystemExit(f"invalid fixture manifest shape: ...")` prints
the **bare** message + `"\n"` (C-2's usage/infrastructure-error class) — no `::error::` prefix;
that prefix is reserved for ED-2's traceback-replacement class (git failures, read failures,
invalid UTF-8), which this port's *other* `loadFixtureManifest` error path (a genuine file-read
failure) still correctly uses.

**F-6 fix.** A new `manifestShapeError` type lets `runFixtureSelfTest`'s manifest-load-error
branch distinguish the two cases via `errors.As`: a `*manifestShapeError` now renders as the bare
`fmt.Sprintf("%v\n", err)`; any other `loadFixtureManifest` error (e.g. a missing file) keeps the
pre-existing `"::error::%v\n"` rendering.

**Verified against real Python, not guessed.** A transient script (written to
`C:\Users\Public\gatecheck_gen_f2.py`, importing `scripts/lib/retired_arch.py` the same way as the
M2-T1 generator, run once against the real CPython 3.14 interpreter, then deleted) confirmed:

* `load_fixture_manifest({"foo.toml": 1, "bar.toml": "accept"})` succeeds (does **not** raise) —
  confirms Python only rejects a non-`dict` top level.
* `f"unknown expectation {manifest.get('foo.toml')!r} in manifest.json"` renders as
  `"unknown expectation 1 in manifest.json"` — confirms `repr(1) == "1"` (Python int repr, no
  quotes), matching this port's `reprJSONValue`/`manifestExpectation.repr()` output exactly.
* `manifest.get('present-empty.toml')` (explicit `""`) reprs as `''` and stays in
  `sorted(e for e in expectations if e is not None)`, while `manifest.get('absent.toml')` (never
  set) is `None` and is excluded — confirms the absent-vs-explicit-empty-string distinction this
  port now preserves.
* `raise SystemExit(f"invalid fixture manifest shape: {path.as_posix()}")` (for a top-level JSON
  array) carries the message `'invalid fixture manifest shape: <path>'` verbatim, with no
  `::error::`-style prefix anywhere in CPython's own `SystemExit(str)` handling (Python's runtime
  prints `str(exc) + "\n"` to stderr for an uncaught `SystemExit(str)`, exit code 1) — confirms
  this port's bare-message rendering is the correct target text.

New tests added in `retiredarch_test.go`:
`TestLoadFixtureManifest_NonStringValue_Accepted`,
`TestManifestExpectation_AbsentVsExplicitEmptyString`,
`TestRunFixtureSelfTest_ManifestShapeError_BareMessage`, and
