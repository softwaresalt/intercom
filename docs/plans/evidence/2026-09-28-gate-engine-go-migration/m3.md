## 2. Local capture-environment notes (not repo behavior)

Two quirks applied during this session's capture and wrapper verification, consistent with the
M1/M2 evidence docs' own notes:

1. Bash invocations that need to reach the Go toolchain use `C:\Program Files\Git\bin\bash.exe`
   explicitly. Plain `bash` on `PATH` on this machine resolves to the Windows-bundled WSL shim
   (`C:\Windows\System32\bash.exe`), which has a separate filesystem namespace (`/mnt/c/...`
   rather than Git-Bash's `/c/...`) and cannot resolve the POSIX-style paths the wrapper scripts
   and Go test helpers (`toBashPath()`) construct. This is the same root cause documented in
   `tools/gatecheck/check_retired_architecture_wrapper_test.go` (lines ~36-50) for M2, and it
   recurs here for the same reason: WSL is installed on this development machine and sorts ahead
   of Git-Bash on `PATH`. GitHub-hosted runners (`ubuntu-latest`, the blocking gate, and
   `windows-latest`, advisory-only) do not have WSL pre-installed, so this PATH-shadowing does
   not occur there, and it is not a CI-affecting defect.
2. **Working-tree CRLF discovery, diagnosed and fixed this session.** After the M3-T7 wrapper
   rewrite, a `bash -n scripts/check-unignore-regression.sh` syntax check (run with plain `bash`,
   without an explicit Git-Bash path override) failed with
   `syntax error near unexpected token $'do\r'`. Investigation showed the working-tree copy of
   the file (134 of its line terminators) had been written as CRLF, even though
   `.gitattributes` declares `eol=lf` for this path (`git check-attr text eol -- scripts/check-
   unignore-regression.sh` → `eol: lf`) — `git` itself independently confirmed the drift with
   `warning: in the working copy of 'scripts/check-unignore-regression.sh', CRLF will be
   replaced by LF the next time Git touches it`. This was a real pre-commit defect (unlike the
   bash-PATH-shadowing quirk above, which is environment-only): a literal `\r` before a bash
   keyword is a genuine syntax error under any POSIX-correct bash, Git-Bash included, not merely
   a Windows-local artifact. It was **fixed** by rewriting the file's line endings to bare `\n`
   (verified via a byte-level CRLF scan showing `0` after the rewrite) before any commit was
   made, so the committed blob is unaffected and clean. `scripts/check-merge-strategy.sh` was
   independently checked and had `0` CRLF sequences throughout — only the M3-T7 wrapper rewrite
   was affected. `bash -n`, `--self-test`, the differential run, and the root-injection guard
   were all re-verified clean after the fix (§8 below).

## 8. M3-T7 — unignore wrapper switch + registration

* `tools/gatecheck/register_unignore.go`'s stub body was replaced with real dispatch to
  `unignore.Run`, following `register_write_path.go`'s and `register_retired_arch.go`'s
  established signature-adaptation pattern.
* `scripts/check-unignore-regression.sh` was fully rewritten from the 483-line Python heredoc to
  a thin wrapper sourcing `scripts/lib/gatecheck-run.sh` and dispatching to the Go binary,
  preserving the original file's RULE / TWO-PART CHECK / NON-VACUITY / NO WAIVER / BOUNDARIES
  documentation banner (with Part 2's description updated to match the Go port's actual
  candidate-union semantics) and adding an M3-T7 migration note.
* **Caller-argument `--root` allowlist guard.** Unlike `check-write-path-precondition.sh`'s and
  `check-merge-strategy.sh`'s wrappers (each forwards a single, non-flag-shaped argument and is
  therefore safe by construction), the unignore wrapper must forward multiple caller-supplied
  flags (`--self-test`, `--base-ref <ref>`, `--head-ref <ref>`). `gatecheck_invoke` in
  `scripts/lib/gatecheck-run.sh` appends the wrapper's own trusted `--root "${ROOT}"` *before*
  forwarding `"$@"`, but `main.go`'s `parseRoot` scans the *whole* argument list for
  `--root`/`--root=` with **last-occurrence-wins** semantics — so an unguarded forward of caller
  arguments would let any caller silently override the trusted root. This is the exact same
  vulnerability class `check-retired-architecture.sh`'s wrapper was hardened against in M2 (real
  PR #83 Copilot round 4/5 finding, confirmed by reading that wrapper's own documented comment,
  not fabricated). Because unignore needs multi-flag forwarding rather than
  retired-arch's single-captured-mode string, the fix here is a loop over `"$@"` that rejects any
  `--root`/`--root=*` argument with `::error::unrecognized argument: --root...` and exit `2`,
  evaluated *before* `gatecheck-run.sh` is even sourced.

### 8.1 Verification

* `bash -n scripts/check-unignore-regression.sh` — clean (after the CRLF fix in §2 item 2).
* `--self-test` — all 5 scenario assertions PASS, matching the Python-era PASS/FAIL line format
  and the T1 golden's `self_test` stream capture (live-count text tolerated per C-5).
* A real `--base-ref HEAD~1 --head-ref HEAD` differential run — PASS,

* The `--root` injection guard — rejects `--root /tmp/evil` with exit `2` and the expected

* `-h`/`--help` — exit 0, unaffected by the guard (neither form matches the `--root` denylist).

## 10. M3-T12 — fold in stash 150364D2 (merge-strategy trap, exit table, rev-parse guard)

Three changes, each independently proven:

1. **Composed single-trap temp-file cleanup.** Added a `MERGE_STRATEGY_TMP_FILES` array that
   every `evaluate_response` temp file is appended to, removed only by the script's one composed
   `cleanup()` trap — not by an imperative `rm -f` call inside the function itself. This avoids
   the double-cleanup / partial-cleanup hazard a function-local `rm -f` would introduce if the
   function is called multiple times across one script invocation (as the self-test does, 16
   times).
2. **Explicit self-test exit-table assertions.** Added PASS→`0`, SKIP→`0`, FAIL→`1` assertions to
   the self-test's `verdict_exit_code` table, alongside the pre-existing unrecognized→`2` row.
   **Red-first proof:** a scratch copy of the script had `FAIL) return 1` changed to
   `FAIL) return 0`; running `--self-test` against the broken scratch copy produced
   `FAIL verdict_exit_code('FAIL reason'): expected exit 1, got 0` — confirming the new assertion
   actually catches the regression it is meant to catch. The scratch copy was deleted immediately
   after, and the real script's `--self-test` was re-run afterward, confirming all PASS including
   the three new exit-table rows.
3. **ED-1 fail-closed guard.** Added `git rev-parse --show-toplevel` **before**
   `gatecheck_build` is invoked, printing `::error::` and exiting `2` on failure — replacing the
   prior behavior of propagating `git`'s own raw `set -e` failure exit code. Per the plan's ED-1
   definition: "Merge-strategy run outside a checkout: today git's `rev-parse` failure code under
   `set -e`; after, 2 with a message" — a deliberate, enumerated, justified-by-150364D2 behavior
   change, not an accidental one. **Proof:** running the script from a scratch non-git directory
   produced exit `2` with the expected `::error::` message, and no `gatecheck_build` attempt was
   made (confirmed no Go build invocation occurred in the trace).

This is distinct from `check-retired-architecture.sh`'s own, older, analogous git-rev-parse guard
(which passes through git's raw exit `128`, not `2`) — the two wrappers have intentionally
different guard behaviors per their respective plan ACs, and this evidence section does not
conflate them.

## 17. Adversarial review (multi-model consensus) — blocking findings and remediation

A separate three-reviewer Adversarial Review (Anchor `gpt-5.6-sol`, Tier-1 `gpt-5.4-mini`, Tier-3
`claude-opus-5`) was run over the same diff and over key M3 decisions (ED-* divergences, test/golden

`docs/reviews/2026-09-30-m3-unignore-mergestrategy-go-port-adversarial-review.md`.

**Initial verdict: BLOCKED.** Two genuine, independently re-verified defects were found (the
reviewer subagents disclosed a sandbox limitation — `git diff`/`git show` could not be run
reliably — so every finding below was independently re-traced by Ship directly against the actual
current source files, by path and function name, before being accepted):

* **C-1 (CRITICAL, 3/3 consensus)** — `internal/unignore/checks.go`'s `splitNulTerminated` silently
  swallowed `pysem.ErrInvalidUTF8` and returned `nil` with no error, collapsing
  `runDifferentialCheck`'s evaluated-candidate count to zero — indistinguishable from the
  legitimate "nothing to evaluate" PASS case — instead of surfacing ED-2's mandated fail-closed
  exit 1 with a one-line `::error::` message. This is an M3-T5-scope INV-1 violation (an
  unenumerated verdict change on an invalid-UTF-8 path), not scope creep: `splitNulTerminated` and
  `runDifferentialCheck` are M3-T5 deliverables.
  **Fix**: `splitNulTerminated` now returns `([]string, error)`; both call sites in
  `runDifferentialCheck` (the `ls-files --others` and `diff --name-only` candidate sources) check
  the new error and return a wrapped `::error::`-prefixed message, matching the existing
  git-failure error pattern in the same function and ED-2's "same exit and same verdict; only the
  message changes" contract. Two new red tests added:
  `TestSplitNulTerminated_InvalidUTF8Propagates` and `TestRunDifferentialCheck_InvalidUTF8FailsClosed`
  (table-driven over both call sites).
* **M-1 (MAJOR, 2/3 consensus)** — `scripts/check-merge-strategy.sh`'s `evaluate_response` allocated
  its temp file and appended it to `MERGE_STRATEGY_TMP_FILES` *inside its own function body*, but
  every call site invokes it as `x="$(evaluate_response ...)"` — bash command substitution always
  forks a subshell, so the array append never reached the parent shell's `cleanup()` EXIT trap. This
  leaked one temp file per self-test fixture call and per live repo scan, regressing the exact
  M3-T12/150364D2-item-1 guarantee this script already claimed to provide.
  **Fix**: `evaluate_response`'s signature changed to `evaluate_response <tmp-file> <json-string>`;
  both call sites (`run_self_test`'s transport-fixture loop and `run_repo_scan`) now allocate the
  temp file and register it in `MERGE_STRATEGY_TMP_FILES` themselves, in the parent shell, before
  invoking `evaluate_response` via command substitution. Verified empirically: a full
  `bash scripts/check-merge-strategy.sh --self-test` run (14 fixtures + 5 exit-code cases, all
  passing) produced zero net new files in the OS temp directory (`Compare-Object` diff of the temp
  directory listing before/after the run), versus the leak the pre-fix subshell design guaranteed.
