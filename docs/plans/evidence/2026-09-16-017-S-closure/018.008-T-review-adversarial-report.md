## 1. Consensus Findings (confidence: HIGH — flagged by all 3 reviewers)

### C-1. `scripts/diagnostic.ps1` resolves all paths against the caller's working directory, not the script's own location

- **Severity**: MINOR
- **Flagged by**: Anchor, Reviewer-A, Reviewer-C (3/3)
- **File**: `scripts/diagnostic.ps1`
- **Issue**: Every path in the `$files` array (`docs/plans/...`, `.backlogit/queue/...`, `docs/archive/plans/...`) and the two `git log`/`git show b65b3e3` commands are evaluated relative to the invoking shell's current directory. The script has no `$PSScriptRoot`-based root resolution and no `Push-Location`/`Set-Location` to the repo root. Confirmed directly: the script content is exactly as carried over, with no path-resolution logic added. Now that the script lives under `scripts/` instead of the repo root, the most natural invocation from its own directory (`cd scripts; .\diagnostic.ps1`) silently reports every path as `NOT FOUND` while still "succeeding" (no error, no exit code signal). This is a **latent** portability issue — running it from the repo root (its likely original invocation pattern) still works today — but the move increases the odds of a broken invocation.
- **Fix**: Resolve the repository root as `Split-Path $PSScriptRoot -Parent` (or via `git rev-parse --show-toplevel`) and use it as the base for every path and `git` invocation, e.g. `Push-Location (Split-Path $PSScriptRoot -Parent)` at the top of the script.
- **Action class**: `advisory` (MINOR severity; the operator carried this file forward verbatim by explicit instruction, so no auto-fix is applied without confirmation — this is a pre-existing debugging/scratch script, not a task-scope deliverable).
- **Secondary note (Reviewer-C only, LOW confidence)**: the script also hardcodes short SHA `b65b3e3` in two `git log`/`git show` commands. This is likely intentional (a one-off diagnostic pinned to a specific investigation commit) rather than a genuine portability defect, but it means the script fails outside a clone containing that object. Advisory only.

## 2. Majority Findings (confidence: MEDIUM — flagged by 2/3 reviewers)

### M-1. Step 1.9's branch-resumption discriminator does not bind the resumed branch to *this session's* scope identity — slug collisions silently merge unrelated Stage scopes

- **Severity**: MAJOR (highest of the two ratings — Anchor rated MAJOR, Reviewer-C rated MINOR; conservative severity taken)
- **Flagged by**: Anchor (P1-BRANCH-IDENTITY), Reviewer-C (P2-COLLISION) — 2/3, same underlying defect described independently
- **File**: `.github/agents/_stage.agent.md`, Step 1.9 item 4 ("Ownership / base-identity / collision discriminator", the two-condition check around the slug-derivation and content-ownership text)
- **Issue — independently verified by the aggregator**: The discriminator proves only (a) shared ancestry with `base_ref` via `git merge-base`, and (b) that the branch's diff touches only the four allow-listed roots. It never proves the pre-existing branch belongs to *this specific* triage/deliberation scope. Two concrete collision paths exist in the algorithm as written:
  1. **Truncation collision**: normalization step (5) truncates the slug to 48 bytes. Two distinct covering-feature titles that share the same first ~48 normalized bytes produce the same branch name.
  2. **Empty-fallback collision**: any session whose slug source normalizes to the empty string uses the fixed literal `stage-session` — every such session, regardless of subject matter, converges on the identical branch name `chore/stage-stage-session`.
  In both cases, a stale, unmerged Stage artifact branch from an *unrelated* prior scope will pass both discriminator conditions and be silently "resumed," mixing two unrelated sets of planning artifacts into one staging PR — a real defeat of the "one Stage artifact branch per scope" intent the gate was written to enforce.
- **Fix**: Add a scope-identity condition to the discriminator — e.g., require the branch's most recent Stage artifact commit to reference the current session's feature/shipment/stash identifier before treating a name match as a resumption — or make the empty-slug fallback session-unique (e.g., a short content hash) rather than a shared fixed literal.
- **Action class**: `manual` — no deterministic one-line fix exists; this requires a design decision about what identity evidence to require (table's default `gated_auto` suggestion downgraded to `manual` because no mechanical fix is available).

### U-7. Branch-existence check only inspects the local ref, not the remote-tracking ref

- **Severity**: MINOR · **Flagged by**: Anchor only
- **File**: `.github/agents/_stage.agent.md`, Step 1.9 item 4, case (1) ("The branch does not exist")
- **Issue**: The non-existence branch is tested only via `git rev-parse --verify --quiet refs/heads/{expected_branch}`. In a fresh checkout, or after local branch deletion, `origin/{expected_branch}` can exist remotely while the local ref does not. The gate would then create a new local branch from `base_ref`, diverging from the pushed remote branch, without ever running the ownership/collision discriminator against the remote branch's content.
- **Fix**: Check both `refs/heads/{expected_branch}` and `refs/remotes/origin/{expected_branch}`; validate a remote-only branch against the same discriminator before creating a local tracking branch, or halt as a collision if it fails.
- **Action class**: `advisory`.
